# 阅读区排版原型：行内提示、行间卡片、卡片动画

2026-10-12，main `757796f`，macOS 27.0.1（26A434），Xcode 27 / Swift 6.4。原始数据见 [evidence.json](evidence.json)：独立视图的部分由原型直接写出；`realReader` 下的四组是从测试输出手工抄入的，要复查请重跑测试，不要以文件为准。

- 第 1、2 节只在**独立的 TextKit 2 `NSTextView`** 上测量。它按 Cairn 阅读区配置：只读可选、`lineFragmentPadding = 0`、等宽 13pt、行高倍数 1.3、可开关换行。但它不是 `ReaderTextView`：没有投影、渲染属性校验器和视口恢复。
- 第 3 节的真实阅读区数字来自真实 `ReaderTextView`，用 [RealReaderCardCostTests.swift](RealReaderCardCostTests.swift) 测得，是 **debug 构建**。release 测试构建被两个无关测试目标挡住：`TypeScriptExtractorTests` 用了只在 DEBUG 下存在的 `$parseObserver`，`PythonExtractorTests:509` 在 release 下报 missing return。所以这些数字是上限。

## 结论

1. **行内提示：两种做法都能画出来，但都有明确代价。现在倾向附件，但还没定。**
   - **加字间距**：不用改投影，但有四个问题要另外处理：点击映射、单词内断行、被选区盖住，以及提示处的范围边界落在空隙中线，光标和高亮会压到提示上。
   - **附件**：交互更像原生，但要给投影加"插入段"，换行时提示会和锚点分开。
2. **行间卡片：两种做法都可行，推荐附件段落。**
   - **附件段落**：卡片在视口上方变高或变矮时，阅读位置不动。代价是投影要支持插入段。
   - **段间距加覆盖视图**：完全不碰投影，但卡片离开屏幕时，它的任何高度变化（比如内容异步加载完成）都要配合 `relocateViewport` 补偿。否则缩小 120pt 会让可见内容跳 16 行。
   - `shouldEnumerate` 可以用来折叠"作为正文段落的卡片"，但原生选区会带上隐藏文字。
3. **卡片动画：在真实阅读区里逐帧改高度的成本很低。**
   - 改一行的段间距并重排、重画，3k 和 5 万行文档上中位数都只有 2–2.5ms（debug），远低于 16.7ms 的帧预算，位移误差为 0。
   - 独立视图里两种卡片做法的 60Hz 动画都没有超过 20ms 的帧间隔。
   - 动画的观感还没有人工确认。

## 1. 行内提示（独立视图）

样本：`let total = compute(items, 42);`，提示为 `: usize`、`values:`、`limit:`。

| 方面 | 加字间距（在锚点字符上加 `.kern`，在背景里画提示） | 附件（插入 U+FFFC，用视图提供者显示提示） |
| --- | --- | --- |
| 点击映射 | 字间距产生的空白里没有自己的字符边界，点击会落到最近的那个边界上。`characterIndexForInsertion` 在提示框内的结果：10% 处是 59（`(` 之前），30–70% 处是 60，90% 处是 61（已经进了 `items`）。锚点字符的分段宽 35pt，正好是字形宽度 7.8pt 加上空隙的一半，所以 `(` 与 `items` 之间的边界落在空隙中线 | 整个提示框都映射到源码位置 60，前后一致 |
| 范围几何 | 从提示处开始的范围，矩形也从空隙中线开始：`items` 的范围从 x=281.87 开始，而字形从 308.87 开始，提前了 27pt。光标、选区边缘，以及 Cairn 按范围画的装饰（同名高亮、括号框、查询下划线）都会压在提示的右半边（用户实测看到光标画在提示中间） | 范围从字形起点开始（308.87 / 308.87） |
| 垂直对齐 | 提示要自己按行片段算基线（`typographicBounds.minY + glyphOrigin.y`）。demo 初版按行片段顶部画，因为 1.3 倍行高把多出的高度放在字形上方，提示整体偏高（用户实测看到） | 附件尺寸是相对基线给出的，TextKit 自动对齐 |
| 鼠标事件 | 提示框所在区域由文本视图接收 | 提示视图默认会接住点击。需要重写 `hitTest` 返回 nil，点击才落到文本视图 |
| 选区覆盖提示时 | 提示画在背景里，会被 TextKit 的选区高亮**完全盖住**（截图里 `values:`、`limit:` 消失）。要改画到选区之上的图层 | 提示视图在选区之上，仍然可见（`hitTest` 返回 nil 时也一样）。这是附件明显更好的一项 |
| 原生选中文本 | 与源码相同 | 含 U+FFFC，复制要按投影去掉（Cairn 的折叠占位符已经这样处理） |
| 放得下时换行 | 正常 | 正常 |
| 放不下时换行 | 空隙算作单词的一部分。`total` 连同提示一起换到下一行；`compute(` 加空隙超宽后，`items` 在单词中间断开（`i` / `tems,`） | 附件本身是断行点。`: usize` 单独换到下一行开头，`values:` 留在行尾而 `items` 换行，提示和锚点分开了 |
| 字号变化 | 间距以点为单位，不会随字号变化，需要重新计算 | 尺寸在每次排版时由提供者给出，自动更新 |
| 与 Cairn 现有管线 | `updateTypography` 会先清掉全文的 `.kern`，`applyTypography` 只给函数名重新写入 0.15 或 0（[CodeInsightReaderUI.swift:4145](../../Sources/CodeInsightReaderUI/CodeInsightReaderUI.swift:4145)、[:4513](../../Sources/CodeInsightReaderUI/CodeInsightReaderUI.swift:4513)）。提示必须在同一趟、函数名之后写入；锚点是函数名最后一个字符时，会覆盖它的 0.15（这一行是读代码得出的，未实测） | 需要给 `ReaderProjection` 增加"无源码字节"的段。目前只有源码段和折叠段（[ReaderProjection.swift:6](../../Sources/CodeInsightReaderCore/ReaderProjection.swift:6)） |
| 其他 | — | 视图半透明时，TextKit 会在它下面画默认的附件图标（折角文档）。视图要先画一层不透明底色 |

## 2. 行间卡片（独立视图）

卡片是一个带边框的面板，里面有自己可滚动、可选择的 TK2 文本视图，放在 300 行文档第 120 行之后。

| 方面 | 段间距 + 覆盖视图（加大锚点行的 `paragraphSpacing`，在空隙里放子视图） | 附件段落（插入 `U+FFFC\n`，视图提供者返回卡片） |
| --- | --- | --- |
| 高度 200→320 | 下一行下移 120pt，无重叠，耗时 1.96ms | 下一行下移 120pt，无重叠，耗时 2.01ms |
| 卡片在视口上方缩小 120pt | 可见内容**跳了 16 行**（顶行从 174 变成 190，约 333pt，远大于 120pt）。这是属性编辑后，卡片与视口之间那段的位置变回了估算值。用 `relocateViewport(to:)` 补偿后回到 174 行，残差 8.5pt（不到半行） | 顶行不变（174→174），前后截图一致 |
| 焦点 | 卡片区域命中卡片内的文本视图，它成为第一响应者，外层选区不变 | 同左 |
| 滚轮（按行） | 滚动卡片内部；滚到底后外层也不动，没有滚动链式传递。前提是卡片里的滚动视图铺满卡片：demo 初版卡片从 1pt 展开，内部滚动视图靠自动缩放，没有撑开，滚轮命中卡片外框，沿响应链交给了外层（用户实测看到外层滚动）。改为在布局时显式铺满后，从折叠展开的路径也命中卡片内的文本视图，滚轮只滚内部 | 同左 |
| 滚走再回来 | 覆盖视图一直在，内部滚动位置保留 | 视图离开窗口；回来后提供者只创建过 1 次、卡片视图只构造过 1 次，说明都没有重建，内部滚动位置保留。这只覆盖单纯滚动的情况：Cairn 的折叠附件按"提供者可能重建"来写（`activeProvider` 是弱引用），属性更新之类的路径会不会重建，这里没有触发 |
| 跨卡片的外层选区 | 文本不含占位符；高亮在空隙左侧露出一条窄带 | 含 U+FFFC；卡片所在行整行高亮，卡片盖在上面 |
| 对投影的要求 | 无，显示文本不变。行号槽跟着移动（真实阅读区截图已确认） | 需要插入段 |
| 位置维护 | 覆盖视图的位置要在每次可能移动锚点行的排版之后自己重算 | TextKit 负责 |
| 与 Cairn 现有管线 | `updateTypography` 会用 `baseAttributes`（含 `paragraphStyle`）覆盖全文（[CodeInsightReaderUI.swift:4147](../../Sources/CodeInsightReaderUI/CodeInsightReaderUI.swift:4147)），卡片的间距必须在同一趟里加回（读代码得出） | 原型给卡片段落单独设了不带 1.3 倍行高的样式；共用正文样式会怎样没有测 |

**`shouldEnumerate`**：卡片作为正文段落，由内容存储委托隐藏。
- `NSTextView` 本身不占用这个委托，我们的委托也确实被调用了。
- 隐藏后，锚点行到下一行的距离从 41.6pt（2 行）变为 20.8pt（1 行）。显示时只让卡片范围失效，就恢复为 41.6pt，耗时 1.2ms；隐藏时让全文失效，耗时 2.5ms。
- 点击映射不会落进隐藏段。
- 但跨过隐藏段的原生选区**包含隐藏文字**：复制或查找要按投影另行处理。

## 3. 卡片动画成本

**真实 `ReaderTextView`**（debug 构建，窗口 1000×800，`fold_perf.rs` 的 3,181 行前缀和 50,002 行全文，换行关和开各一组）：

| 操作（中位数 / p95，ms） | 3k 行，换行关 | 3k 行，换行开 | 5 万行，换行关 | 5 万行，换行开 |
| --- | --- | --- | --- | --- |
| 段间距逐帧变化 16→240→0pt（30 帧） | 1.95 / 2.42 | 2.51 / 2.99 | 2.18 / 2.71 | 2.22 / 2.60 |
| 让视口中一行失效、重排、重画 | 0.65 / 0.70 | 0.68 / 0.82 | 0.66 / 0.73 | 0.67 / 0.72 |
| 折叠或展开一个 11–12 行的块（同步部分） | 15.89 / 16.48 | 16.15 / 22.94 | 51.41 / 72.12 | 50.00 / 54.16 |

- 段间距每一帧之后，下一行的实际位移与设定值的误差都是 0pt。
- 折叠切换的耗时随文档变大而增加，不适合拿来逐帧做动画；逐帧改高度应该走"只改一段的高度"这条路。
- 附件段落做法在真实阅读区里没法直接测，因为要先实现投影插入段。它每帧做的事是"让附件那一段失效并排视口"。在真实阅读区里，这件事的代价下限是上表第二行（0.65–0.68ms，与文档大小无关），上限是第一行（段间距还多一次存储编辑）。独立视图里两种做法的成本也相当。

**独立视图 60Hz 动画**（18 帧，0→240pt，ease-out）：
- 段间距做法：每帧工作中位数 2.35ms，最大 4.33ms，最大帧间隔 17.55ms，没有超过 20ms 的帧。
- 附件做法：每帧工作中位数 2.19ms，最大 4.00ms，最大帧间隔 17.94ms，没有超过 20ms 的帧。
- 几次运行之间中位数在 1.8–2.8ms 之间波动，结论不变。

## 未验证（BLOCKED / 人工目视）

- **真实鼠标点击和拖选：BLOCKED。** 用 `postEvent` 预先排队 mouse-up 再发 mouse-down，`NSTextView` 的跟踪把光标全部放到了文档末尾，所以去掉了这种合成方式。点击映射改用 `characterIndexForInsertion` 测量，这是 `NSTextView` 把点击映射到字符位置所用的方法。拖选只按两端的映射构造选区，再截图。
- **方向键：没有验证。** 合成的 keyDown 在只读视图里，卡片内和外层对照组都不移动光标，说明这种测法本身无效。所以只能证明键盘事件会送到卡片（它是第一响应者），不能证明光标能在卡片里移动。
- **用户实测（2026-10-12，修复后的 demo）**：字间距提示与正文对齐；点击提示左半边落在 `(` 之前；卡片展开后指针在卡片内滚动，外层不动。用户同时看到两个问题，都已在第 1 节记录：选中后提示被盖住；光标画在提示中间。
- **真实滚轮和触控板：用户已在修复后的 demo 里确认外层不动。** 原型里的滚轮是直接交给命中视图的 `scrollWheel`，不是窗口服务器送来的事件。用 `CGEvent.postToPid` 投递到本进程的滚轮事件，内外两层都没有反应，说明这种测法无效，已经去掉。用户在 demo 初版里实测到外层滚动，原因是上面那个卡片布局 bug；修好后用户确认外层不动，但没有分别说明鼠标滚轮、触控板和惯性滚动的表现。
- **动画观感、提示和卡片的视觉效果：需人工目视。** 用下面的 demo 窗口查看。只读 `NSTextView` 不画插入点，Cairn 阅读区也一样，所以 demo 用一条红色竖线标出光标，并在标题栏显示它对应的源码位置和前后文字，方便判断点击落点。
- **release 构建下的真实阅读区数字：BLOCKED**，原因见开头。
