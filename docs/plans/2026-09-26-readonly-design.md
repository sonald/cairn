## 1. 设计目的与基线

Cairn 的核心操作是阅读某份已经捕获的源码。对于相同内容，点击、滚动、展开调用关系、改变颜色等操作，应复用已经获得的信息。对于折叠、字号和窗口宽度变化，应只更新受到影响的投影或布局。

本设计将这条产品假设落实为数据生命周期、查询结构、显示事务和可检查的工作量约束。近期交付集中于现有阅读体验的响应性与正确性；分块内容提供器和非文件顺序阅读视图通过独立原型验证后，再决定是否进入产品。

### 1.3 完成的判定单位

分为三个可独立验收的交付包：

- **A：交互查询与装饰复用。** 标识符索引、gutter 数据、折叠拓扑、调用归属。
- **B：显示更新与布局边界。** 失效分类、投影与文本物化分离、局部文本更新、统一重排策略。
- **C：阅读投影原型。** 分块布局与跨文件阅读组合的可行性证据。

A、B 的验收范围明确可执行；C 的产出可以是有证据的采用或暂缓决定。C 不影响 A、B 独立交付。

## 2. 使用场景、需求与不变量

### 2.1 典型场景

**连续阅读同一个函数。** 用户先点击 `request`，再滚动查看它的使用，随后折叠一个与它无关的函数。标识符的源码出现列表保持有效；滚动查询可见范围；折叠只改变命中的显示投影与隐藏计数。

**检查大型模块。** 用户把文件切成 Overview，再展开一个小函数。文档字节、语法、大纲、行表和局部绑定仍是同一份数据。系统计算新的显示段，更新变化区间，并在真实布局后恢复当前源码锚点。

**切换主题与连字。** 颜色变化更新色彩、覆盖层和附件外观；连字变化通过已有字体解析器更新排版。两者同时变化时只发生一次有序事务，源码位置和投影段保持有效。

**外部编辑后继续阅读。** 磁盘文件被 IDE 修改，旧快照仍代表原内容。Cairn 继续按现有规则显示 stale 状态并允许显式刷新。旧任务可以完成缓存计算，但不能把结果发布到新快照的视图上。

### 2.2 需求编号

| 编号 | 要求 | 可观察结果 |
| --- | --- | --- |
| R01 | 阅读操作保留源码快照身份 | 内容哈希不因折叠、主题或排版变化而改变 |
| R02 | 明确源字节、显示 UTF-16、字形与像素坐标 | 中文、emoji、组合字符、连字下选择和跳转正确 |
| R03 | 同名出现查询复用索引 | 派生数据就绪后，重复点击不扫描全文 |
| R04 | 保留同名出现与同一绑定引用的区别 | 同名遮蔽变量不会被错误解释为同一绑定 |
| R05 | Gutter 绘制只消费准备好的数据与可见几何 | 稳定状态滚动不重建文档级映射 |
| R06 | 折叠结构关系预计算 | 父、子、兄弟与子树查询不重新做全体包含分析 |
| R07 | 调用所属定义预计算 | 外向调用查询不逐调用遍历全部 executable regions |
| R08 | 按依赖分类失效 | 纯颜色更新不替换文本；纯排版更新不重建投影 |
| R09 | 投影描述与文本物化分离 | 空投影构造不解码整份源码；局部折叠可更新局部文本 |
| R10 | 异步结果按内容、分析与请求归属发布 | A→B→A、刷新、关窗不会收到过期 UI 更新 |
| R11 | 重排保留完整阅读状态 | 正常可恢复状态下，源码锚点与选区保持；不能恢复时有明确状态 |
| R12 | 缓存与任务有生命周期和预算 | 反复切文件、版本和窗口后，无持续增长的无主数据 |
| R13 | 现有阅读面和安全边界得到维持 | 字体、连字、wrap、复制、证据、Safe Mode 和本地化可回归验证 |
| R14 | 功能与工作量都能自动验收 | 测试有完整结束摘要；计数有实际工作点支持 |
| R15 | 新阅读投影可以逐段回到来源 | 重排和重复展示区分显示实例，生成文本有独立来源类型 |

### 2.3 必须保持的约束

1. `ContentID` 对应一份确定的源字节。相同路径的新内容必须获得新的内容身份。
2. 源码范围采用现有 `ByteRange` 的半开区间约定。EOF 是合法位置，但不是一个非空 token。
3. 源码身份稳定不代表分析数据永远不变：纯文本阶段、语法就绪阶段、分析规则升级必须区分。
4. 核心与模型模块继续禁止 AppKit/SwiftUI 导入；UI 对象留在 MainActor。[S1][S7]
5. 不通过插入空格、换行或替换运算符实现视觉效果。显示投影与复制的源文本分别管理。[S9]
6. 冻结 Reading Set、书签、导航证据继续绑定自己的内容与快照。旧证据不被新版分析静默覆盖。
7. 局部更新是内部显示存储操作。用户仍不能修改源码；外部文件变化校验、权限和安全限制继续有效。
8. 新增运行时缓存不写入用户仓库。第一批优化采用可丢弃的内存派生数据，避免引入必需的持久化迁移。

## 3. 架构与模块边界

### 3.1 数据流

```text
捕获的源码 / ReaderDocument
  ├─ 已有：行表、字节映射、语法、大纲、局部绑定
  └─ 新增派生数据：标识符表、折叠拓扑、静态装饰
          │
          ▼
阅读状态：当前关注对象、逻辑折叠集合、Reading Height
          │
          ▼
ReaderProjection：源片段 + 折叠占位，带版本的纯数据
          │
          ├─ DisplayMap：坐标映射兼容入口
          └─ ReaderProjectionMaterializer：需要时生成显示文本/变化片段
                         │
                         ▼
               ReaderTextCommitter：MainActor 上的显示提交
                         │
                         ▼
               TextKit 布局 → 可见几何 → 装饰绘制
```

`EngineSession` 中的调用归属索引独立于上述 UI 流程。它依赖 `ContentIndex`，为现有关系查询提供更直接的输入。

| ReaderCore | `IdentifierIndex` | token 定位、名称倒排、匹配结果视图 |
| ReaderCore | `FoldTopology` | 折叠父子关系、ID 查询、子树连续区间 |

### 3.3 数据共享的单位

共享不可变源码与派生结构，视图实例分别持有逻辑折叠、选区、滚动位置、布局管理器和附件实例。相同文件在主 Reader、Context、Compare 中可以共享派生数据，但三者的宽度、可见范围和选区可能不同。

`NSTextView`、`NSTextStorage`、布局片段和可变附件不进入跨视图共享缓存。`ReaderFontResolver` 继续只缓存字体，不能被扩展成文档或视图的全局持有者。[S5]

## 4. 身份、版本与失效模型

### 4.1 四层身份及分析版本

| 身份/版本 | 包含的输入 | 不应包含的输入 |
| --- | --- | --- |
| 内容身份 | `ContentID` | 路径显示名、主题、滚动位置 |
| 分析身份 | 内容、语言模式、grammar/extractor/Reader 分析规则版本、分析阶段 | 字体和视口 |
| 投影身份 | 内容、可见显示段、占位符语义来源 | 颜色、字号、滚动位置 |
| 排版身份 | 投影、影响度量的语法版本、`ReaderTypographyKey`、有效文本宽度、wrap、字体环境、必要的附件度量 | 当前高亮颜色 |
| 绘制身份 | 投影/几何、颜色、搜索/关注范围、diff/书签/hover 的修订 | 源码的新身份 |

四个更新层是内容、投影、排版、绘制；分析身份额外描述内容派生物。它解决“同一个 ContentID 的纯文本对象升级为语法对象”的问题。

`syntaxFormatting` 同时影响字体和部分绘制规则，应同时触发相关动作。`lineNumbers` 是否影响排版，取决于 gutter 是否改变有效文本宽度。系统外观变化虽然可能沿用动态颜色，也必须正确使可见绘制和附件外观失效。

新的 `ReaderAnalysisKey` 使用现有版本信息并增加 Reader 派生算法版本。测试直接构造自定义 spans/folds 时，必须显式提供独立分析身份，或绕过跨对象缓存；不能把两份不同分析内容放进同一个键。

### 4.2 事务编号不等于缓存键

`loadGeneration`、`navigationGeneration`、视口事务编号解决的是“结果还归不归当前请求”。它们不能替代内容身份，也不能无条件加入所有缓存键，否则每次导航都会失去复用。

相同内容在另一个视图出现时，派生数据可以复用。回调发布仍必须检查该视图的订阅编号、关闭状态、内容身份和分析身份。切换后返回 A 时，A 的旧构建可以成为缓存命中，但只有新订阅可以更新当前视图。

### 4.3 更新矩阵

`复用` 表示保持现有产物；`更新` 表示相应层确实需要新产物。

| 事件 | 源码/分析 | 投影段 | 文本字符 | 排版 | 绘制 |

| 稳定状态滚动 | 复用 | 复用 | 复用 | 请求新可见范围 | 更新可见装饰 |
| 点击已有标识符 | 查询已有索引 | 复用 | 复用 | 通常复用 | 更新旧/新命中范围 |
| 仅切换颜色主题 | 复用 | 复用 | 复用 | 度量未变时复用 | 更新颜色与附件 |
| 仅改透明度 | 复用 | 复用 | 复用 | 复用 | 更新受影响属性 |
| 字体/字号/连字变化 | 复用 | 复用 | 复用 | 更新属性与布局 | 重绘 |
| 改变 wrap/有效宽度 | 复用 | 复用 | 复用 | 更新段落与布局 | 重绘 |
| 折叠变化且可见段改变 | 复用 | 更新 | 应用局部差异或明确全量回退 | 受影响布局 | 更新投影汇总 |
| 关闭祖先内改变子折叠状态 | 复用 | 可见段相同时复用 | 复用 | 复用 | 仅有可见状态时更新 |

### 4.4 计算更新计划

`ReaderUpdatePlan` 是一组可合并的动作，例如 `replaceDocument`、`rebuildProjection`、`patchCharacters`、`updateTypography`、`updateParagraphs`、`refreshDecorations`、`redraw`。它根据输入身份和实际变化计算，不依赖回调函数名称。

一次设置提交可能同时改变字体、颜色和 wrap。先合并成一个计划，再捕获一次状态、提交一次、恢复一次。纯颜色路径应直接更新绘制，避免无条件经过 `configureGutter` 和视口恢复。

所有对字符、属性、映射的写入都经统一提交入口；小型当前行/hover 绘制可有独立轻量入口，但不得间接重建投影。

## 5. 标识符索引与派生物构建

### 5.1 保持现有匹配语义

当前 `identifierOccurrences(at:)` 的选择 token 与匹配过滤逻辑不是完整语言解析器：它使用 Unicode 标识符规则识别 token，再用高亮范围排除部分命中。[S2]

第一阶段以现有函数作为测试参考实现，优化其数据访问方式。Rust raw identifier、Python 关键字、TypeScript `$`、TSX、注释/字符串内的点击行为都要先记录基线。即使某项基线行为不理想，也应以独立行为变更记录修正，避免把语义变化混进性能改造。

尤其注意：原逻辑使用 Swift `String` 相等比较。倒排表不能自行换成未经定义的字节相等或大小写折叠；Unicode 规范等价字符串的匹配结果须与参考实现一致。源码范围仍使用原始字节，不把规范化后的文字写回文档。

### 5.2 数据结构

建议使用连续数组与名称驻留，减少每次点击的临时分配：

```swift
// 接口示意；类型名为本设计新增约定。
package struct IdentifierToken: Sendable {
    let range: ByteRange
    let nameIndex: UInt32
}

package struct IdentifierIndex: Sendable {
    let tokensBySource: [IdentifierToken]
    let names: [String]
    let namesToIndex: [String: UInt32]
    let postingOffsets: [Int]
    let occurrenceRanges: [ByteRange]
}
```

`tokensBySource` 用于从点击位置定位原 token。它应保留参考实现能够选中的 token，包括“可以作为查询词但不会进入结果”的位置。`occurrenceRanges` 则只收纳通过当前语法过滤规则的结果，并按名称分组、组内按源位置排序。名称的结果范围由 `postingOffsets[i]..<postingOffsets[i+1]` 表示。

查询先在 token 起点数组二分，再通过名称编号取得结果切片。对相同关注对象，UI 保存不可变切片或轻量句柄，折叠和滚动不再重新执行源码检索。对可见高亮继续二分结果范围，避免每帧遍历全部命中。

不要求第一版必须采用压缩整数、位图或自定义 allocator。先记录实际内存，连续数组足以获得明确的生命周期与查询边界。

### 5.3 构建算法

1. 验证输入为当前系统支持的 UTF-8 文档；沿用现有字节边界约束。
2. 将需要排除的 spans 变成按位置排序的区间；正确处理重叠与相邻区间。
3. 单次遍历 Unicode scalars，产生 token 范围与名称；维护源字节位置。
4. 用单调区间游标判定 token 是否进入结果，不为每个 token 扫描全部 spans。
5. 按名称收集结果，生成连续 posting 数组和偏移表。
6. 发布不可变索引，并记录读取字节数、token 数、分配估算与耗时。

设文档字节数为 N，token 数为 T，排除范围数为 H，命中数为 K。构建目标为 O(N + T + H)，前提是输入区间已排序；若需要排序，单独记录排序成本。热查询定位为 O(log T)，取得切片为 O(1)，真正消费结果仍需 O(K)。不能把包含 K 条结果的完整绘制声称为 O(1)。

### 5.4 异步就绪与共享

建议通过一个有作用域的 `ReaderDerivedDataStore` 管理异步构建。它接收已存在的 `ReaderDocument`，从当前分析数据生成派生索引，保证同键只有一个构建任务。它不为索引再启动一次 tree-sitter parse。

状态明确区分：

```text
notRequested → building → ready(index)
                       ↘ unavailable(reason)
```

新文档的首屏允许先显示已有内容。用户在索引构建中点击时，保存该视图最新一次查询意图；就绪后仅在内容、分析身份、订阅和关注对象仍匹配时发布。长时间未就绪可在已有状态通道显示本地化提示；`building` 不应伪装为 `ready([])`。

运行时 UI 调用点统一改用已准备索引。旧全文扫描实现仅留在测试参考路径，不在索引缺失时自动退回主线程扫描。大文件纯文本阶段与语法就绪阶段使用不同分析身份；语法结果到达后需重新计算排除范围相关的派生数据。

现有 `public identifierOccurrences(at:)` 的签名需要单独迁移。为保持源码兼容，可以保留带弃用说明的同步包装器，使用新 builder 计算结果并明确其构建成本；所有 Cairn 交互调用者改用 prepared data。该包装器不能成为 UI 的未就绪回退路径。旧算法仅用于测试对照。

首次版本可以在完成语法分析后构建一份索引。只有性能证据要求时，才把“原始 token 表”和“语法过滤后的 posting 表”进一步拆成可共享的两个产物。

### 5.5 局部绑定引用

已有 `localBinding(at:)` 和 `referencesByBinding` 继续作为绑定查询来源。[S2] 内部查询类型应明确选择 `sameSpelling` 或 `sameBinding`。没有足够绑定信息时，返回带状态的结果；是否允许界面降级为同名出现，应由交互入口决定，并保留相应语义说明。

第一批优化不改变现有默认点击含义，也不把局部语法绑定升级成跨文件、精确类型解析结论。

## 6. 静态关系索引

### 6.1 折叠拓扑

`FoldTopology` 基于经过验证的 `foldRegions` 构建以下数据：

| 数据 | 用途 |
| --- | --- |
| `regionIndexByID` | 从 FoldID 直接定位区域 |
| `parentIndex` | 查找父折叠区域 |
| `children` / 子项连续范围 | 展开同级或递归子项 |
| `preorderIndices` 与 `subtreeEnd` | 枚举子树，不重复测试包含关系 |
| `headerLine` | Gutter 与跳转使用的源逻辑行 |
| `associatedFacetIndex` | 作用域聚焦与大纲关联 |

对于合法、无交叉区间，按起点升序、终点降序排列，用栈构建嵌套树。相同范围、相同头行、不同折叠类型需要稳定的 tie-break，必须复用当前归一化及选择规则。不能仅根据 `outlineDepth` 猜父子关系。

发现交叉区间时，先判断它是否已被现有折叠归一化排除。对仍存在的输入，保留兼容查询或拒绝构建该部分拓扑并报告诊断；不要在栈算法中静默丢失区域。测试中必须包含这类异常。

逻辑折叠集合与实际渲染的最大折叠集合继续分开。关闭祖先时，子折叠状态仍保存；在祖先内部修改子状态，若可见段不变，应只更新阅读状态，不能增加投影版本或安装文本。

第一版允许在实际折叠变化时 O(F) 重建最大集合和装饰汇总。目标是把这项工作从滚动、hover 和重复查询中移除。后续有数据后，再考虑更复杂的增量树结构。

### 6.2 调用所属定义

`CallOwnershipIndex` 在 Engine 模块中构建：

```text
regionID → executableRegions 中的索引
callIndex → ownerFacetIndex（可空）
facetIndex → 按源码顺序排列的 callIndex 切片
```

归属规则严格保持 `outgoingCalls` 当前行为：从包含调用起点且有关联定义的区域中，选范围最小者；同长度按现有 region ID 规则打破平局。加入定义的调用列表前，仍校验整个 call range 位于该定义 facet 的范围内。[S6]

匿名闭包、嵌套函数、默认参数中的调用、方法与顶层执行区分别测试。这里保存的是语法归属；调用到底指向哪个目标，继续交给现有 Resolver。

可以使用按位置扫描的活动区间集合构建归属。由于输入不一定满足简单树假设，对交叉范围使用能够按“长度与 ID 优先级”选择活动区域的数据结构。构建复杂度目标为 O((R + C) log R)，其中 R 为区域数，C 为调用数。热查询枚举已有调用列表，仍执行必要的语义解析。

`outgoingCalls` 的 512 条限制、排序、`truncated` 标志、候选证据与可信度保持原规则。[S6] 新索引不能把截断后的数组当成完整调用数，也不能缓存旧 Exact 会话的结果冒充当前答案。

### 6.3 生命周期与缓存键

折叠拓扑随 Reader 分析产物保留；调用归属随对应 `ContentIndex` 的有效作用域保留。第一版不改变持久化 `ExtractionDraft` 的编码。

调用索引中包含 facet/region 或名称驻留编号时，需要保持其所属 store 一致。跨 store 的缓存不得只按 `ContentID` 返回带旧编号的对象；最简单的方案是把该缓存留在 store/session 作用域内，以现有 `ContentIndexKey` 分组。

## 7. Gutter 与渲染属性

### 7.1 装饰数据的三个生命周期

**文档级数据**包括声明所在源行、折叠头所在源行、ID 与区域的对应关系。构建后随分析身份保持不变。

**投影与标记数据**包括未被隐藏的折叠头、隐藏区间中的 diff/书签/命中汇总，以及一行上多个候选采用哪一个。它依赖投影版本和各标记修订号。

**可见几何数据**包括当前 TextKit fragment/视觉行的矩形、裁剪与鼠标命中位置。它随布局和视口变化。

`drawRuler` 只读取前两者，并枚举已布局的当前可见几何。旧实现里在绘制前构建 `foldsByLine`、`regionsByID` 和折叠 diff 的逻辑移到数据发布入口。[S3]

### 7.2 更新规则

- 折叠变更：更新当前投影对应的标记汇总。
- diff/书签变更：仅更新相关的标记派生数据。
- 同名出现或搜索变更：保存源范围，重新计算隐藏计数和显示范围；不扫描源码。
- 当前行、hover、临时导航标记变更：更新对应可见行的绘制状态。
- 稳定状态滚动：查询源行/显示区间并绘制；不构建文档字典。

折叠隐藏计数可以利用排序范围的 lower-bound 查询得到。处理包含关系时仍遵从现有语义，例如选择占位符时复制隐藏源码，gutter 标记落在首视觉行。滚动到续行区域不能出现重复折叠箭头，也不能把整列当作 hover 命中区域。[S9]

### 7.3 版本缓存与 TextKit 回调

`RenderingAttributesCoordinator` 可以缓存语法范围与显示范围组合得到的“属性计算结果”。缓存键至少包含分析、投影、相关绘制修订；缓存长度应受限。

**TextKit 调用 `renderingAttributesValidator` 时，不能仅凭自有版本号相同就跳过属性设置。** 框架可能已经使自己的属性状态失效。安全的优化是复用属性计算结果，再按照回调要求重新提交；只有应用明确知道对应框架属性仍有效时，才可省略额外的应用主动验证。[A1]

布局片段的对象地址也不足以作为长期缓存身份。片段销毁、范围变化、manager 更换和系统失效都必须清理相关状态。任何弱引用/身份表都应有容量与淘汰策略。

### 7.4 折叠附件颜色

当前附件携带主题相关信息，主题变化会走重新投影路径。[S3] 调整为：不可变的来源和摘要数据，加上 MainActor 管理的外观状态。

仅颜色变化更新已有附件及已创建 provider 的外观，并保证稍后创建的 provider 也读取最新外观。文字、字体、localization 或实际测量尺寸发生变化时，升级为排版更新。

固定宽度的命中计数变化可走绘制路径，但这个前提必须被测试，而不能只由调用者声明。

纯颜色更新还需要覆盖没有语法 span 的基础文本色、空语法文档和随后进入视口的文字。关注对象改变时清除旧命中的覆盖属性，再应用新范围；不能仅更新有颜色的语法 token。使用默认属性、范围属性或 rendering attributes 的选择由原生验证决定，实际属性访问量单独记录。

## 8. 投影与文本物化

### 8.1 第一版投影模型

```swift
// 接口示意；第一版只支持单文档、按源顺序展示。
package enum ReaderProjectionSegment: Sendable {
    case source(range: ByteRange, utf16Length: Int)
    case folded(id: FoldID, hidden: ByteRange)
}

package struct ReaderProjection: Sendable {
    let contentID: ContentID
    let segments: [ReaderProjectionSegment]
    let displayUTF16Starts: [Int]
    let displayUTF16Length: Int
}
```

投影保存源范围和显示长度，不保存完整 `projectedString`。折叠占位沿用当前一个 UTF-16 单元的约定。源到显示、显示到源、占位符对应隐藏区间及可见源范围查询由纯映射逻辑完成。[S10]

无折叠投影只有一个源段，长度从已有映射读取；创建它不需要重新解码全文。物化层只有在首次安装、明确全量回退或生成变化片段时才解码对应源范围。

### 8.2 构建与验证

构建边界校验：所有区间在文档范围内、字节边界可映射、显示长度计算无溢出、FoldID 有效、渲染隐藏范围互不交叉、源顺序单调、前缀长度一致。

验证通过后发布一个不可变投影。内部热点可以依赖这些已验证条件；外部输入、跨快照导航、磁盘内容和持久化状态仍使用原有防御检查。

`DisplayMap` 在迁移中成为适配器。先让它委托新投影，但完整物化结果与旧实现逐字节/UTF-16 对照；通过后再接入局部更新。

### 8.3 局部差异算法

第一版无需通用字符串 diff。对新旧单调投影使用源区间与占位符来源计算差异：

1. 合并新旧折叠边界，将能够共享的 source slice 对齐成相同区间。
2. 比较对齐后的源段与占位符身份，找到实际变化区间。
3. 合并相邻变化，输出以**旧显示坐标**表示的替换范围与新的投影片段。
4. 对每个新片段生成 attributed text，并准备相应附件和段落属性。
5. 同一事务中按旧坐标从后向前替换，避免前面的更新移动后续 patch 的坐标。

不能只对整个 segment 的 ID 做最长公共前缀比较。旧投影可能只有一个全文件 source slice，而新投影把它切成三段；如果不先按源边界细分，会把一次小折叠误判成全文件替换。

第一版允许投影元数据计算为 O(S_old + S_new + P) 或包含必要排序的相应复杂度，其中 S 是段数，P 是变化区间数。需要解码/物化的文字目标是变化部分及必要的相邻段落上下文。

**局部替换并不保证整个 TextKit 操作为局部时间。** `NSTextStorage` 可能移动尾部存储，布局也可能传播。工作量门禁分别记录应用层物化字节、存储替换范围与原生布局成本。[A2][A3]

### 8.4 显示提交协议

提交必须在 MainActor 上同步完成，事务中不使用 `await`：

1. 检查内容、分析、旧投影版本与目标视图是否仍匹配。
2. 校验所有旧 NSRange、替换顺序、预期新长度与附件位置；发现问题先选择回退。
3. 捕获完整选区、潜在隐藏端点、视口源码锚点与水平位置。
4. 暂停会观察中间映射的应用回调与 rendering validator，进入 `performEditingTransaction`。
5. 修改 backing storage，安装新映射/附件状态，使对外发布时两者一致。
6. 恢复 validator，结束事务，按需要恢复选区与视口并发布一次变化。

系统文本事务用于让文本系统响应内部更新，是继续保留的正确接口。[A3] 不要求在每个字符替换过程中对外暴露可查询状态。

Objective-C 范围异常不能作为常规 Swift 错误恢复机制。要在修改前完成边界检查。预检失败时记录原因，采用经过验证的新投影全量安装；无法构造合法投影时保留旧显示状态并报告失败。

调试构建可比较新投影物化的完整文本与实际 storage。正常发布热路径仅做长度、受影响区间和版本校验，避免“为了验证增量正确性又每次扫描全文”。

### 8.5 选择、复制与隐藏端点

同一投影下的排版变化可以复用完整显示选区和 affinity。投影变化时，选区两端都应转换成源锚点，分别记录与占位符的关系；不能只保留一个零长度插入点。

源锚点必须表达 EOF、空文档、隐藏区间内端点以及左右边界倾向。折叠隐藏了选择端点时，保存 latent source anchor；重新展开后恢复其原来源位置。多选区逐个转换。

单调文件阅读中的复制保持当前约定：显示范围通过映射获得源范围，选中折叠占位时包含相应隐藏源码。复制与拖拽导出使用相同来源逻辑。未来跨文件/重复展示的复制策略在 §12 单独定义。

### 8.6 段落与连字边界

局部 patch 不能在末尾又调用遍历整份显示文本的段落重建。`ReaderParagraphLayout` 增加受影响范围入口，并维护不可变的源段落前导空白信息；必要时扩展到相邻完整段落。[S4]

Tab 度量继续复用现有测量与字体解析规则。源行前导空白与显示行前导空白通过 source mapping 区分，防止折叠拼接改变悬挂缩进含义。宽度变化可能影响所有带缩进的段落，应按排版变化记录实际工作，不能错误声称只更新一个 patch。

相邻文字的连字形成由真实字体布局负责。patch 需要使边界相邻的布局失效，属性应用必须移除不再适用的 `.kern`、`.ligature` 等旧值。测试同时覆盖连字开启、关闭、字体默认和字体回退。

当前 `ReaderParagraphLayout` 使用独立的 `NSLayoutManager` 测量 Tab 前缀；它没有访问 Reader 的 `view.layoutManager`，不应被误判为 Reader 已降级为 TextKit 1。[S4] 对主阅读视图应避免请求旧 `layoutManager`，并通过原生测试检查仍使用 TextKit 2。[A4]

## 9. 统一重排与大文件策略

### 9.1 沿用已经完成的工作

当前实现已经保存视口状态、合并宽度通知、使用有限次后续修正，并在部分大文件关闭折行路径使用视口估算。[S3] 本次将这些机制整理成共同的重排事务，减少不同入口的策略偏差。

入口至少包括：设置更新、窗口/分栏宽度变化、语法结果到达、折叠投影提交、字体环境变化。公开导航和用户主动滚动仍保持其各自语义，不与纯重排恢复混为一次操作。

### 9.2 文档成本

在现有 `FileTier` 之外增加成本描述，首先记录：

```text
byteCount
logicalLineCount
maximumLineByteLength
highlightSpanCount
foldRegionCount
projectedUTF16Length
当前已布局视口及最大已知段落布局成本
```

字节数和最长源行可以在源元数据构建中一次收集。字体、wrap 后的视觉高度属于布局输入，不能固化进源码身份。

8,000 行阈值作为当前策略的起点保留，不在本文中凭空替换成另一组声称“最优”的阈值。S0 用固定 fixture 收集长单行、混合 Unicode 和大量折叠区域的结果，再冻结新的策略配置。

超出 `UInt32` 源范围能力、整数转换失败、无效 UTF-8 等情况，按可解释的加载失败或当前支持边界处理。优化不得通过截断偏移来假装支持更大文件。

### 9.3 事务状态

```text
idle
  → captured(old stable reading state)
  → applying(new attributes / projection / container)
  → awaitingLayout
  → restoringAnchor
  → stable
```

中间任何阶段收到更晚的用户操作、导航、内容替换或关闭事件，都可以进入 `cancelled`。新的连续纯重排可以复用最初稳定锚点，但必须合并到最新目标配置；旧的 correction 不能把用户新滚动的位置拉回去。

每个事务带有内容、分析/投影、目标排版身份和视图请求序号。恢复前同时检查版本和几何是否对应目标容器。颜色变化直接走绘制更新，不启动此状态机。

### 9.4 视口锚点

源位置是持久的定位依据。状态至少包括：

- 视口内一个可识别的源字符/EOF 锚点，以及它到视口顶部的像素偏移。
- 完整选区及 selection affinity；当前行标记可与选区锚点不同。
- 关闭折行时的水平位置；开启折行时暂存该值。
- 隐藏区域中的 latent anchor，以及当前投影版本。

纯排版变化优先使用相同投影的显示选区，避免多余往返转换。投影变化则使用源锚点恢复。恢复失败原因分为：内容已变、位置隐藏、尚无布局、视图已关闭、用户操作覆盖，以及目标几何不可用。只有可重试的布局未就绪进入有限次后续修正。

### 9.5 大文件与未知范围

已知大文件有旧视口起点时，复用当前估算策略。没有旧视口起点时必须有独立测试：不能因为缺失锚点就自动落入全文件同步布局并造成长时间阻塞。

远处的文档高度允许使用框架估算，当前视口的来源定位和已显示几何必须准确。滚动条范围收敛要有观测值，避免用一个“布局已完成”的布尔值掩盖估算状态。

超长单段落可能使一次 viewport layout 本身很昂贵。有限次数的重试不能限制单次调用耗时。此情况先报告并记录独立性能场景；只有 §12 的分块内容/布局原型证明可行后，才引入更复杂的解决方式。

### 9.6 Reading Set 与其他阅读面

| 阅读面 | 本次约定 |
| --- | --- |
| 主 Reader / Compare / Context | 共用更新计划和字体解析，分别管理视口与选区 |
| Settings 预览 | 复用实际阅读组件；纯数据测试不替代可见窗口测试 |
| Reading Set 卡片 | 内容不变时复用卡片和语法产物；外层管理纵向锚点；卡片管理局部选择与水平位置 |
| 普通文本 | 保留全局 wrap 规则，使用普通文本的段落策略 |
| Markdown / HTML / PDF / 图片 | 继续遵从各自渲染器的布局规则 |

这些阅读面规则延续已有 wrap 设计。[S9] 本次新增的数据索引不要求所有非代码预览也构建语法或标识符表。

Reading Set 的进一步卡片虚拟化列入后续可选优化。近期先验证纯颜色变化不触发重新测量，字体/宽度变化的测量结果按真实配置缓存；不以固定行高估计替代实际复杂排版。

## 10. 并发、内存与失效传播

### 10.1 并发模型

不可变数据构建在 worker 上完成，AppKit 状态在 MainActor 上提交。派生数据服务用 actor 或受控锁保护缓存登记，锁内只查找、登记和发布，不执行完整分析。

`inFlight` 在等待构建结果前登记，避免 actor 重入期间同键启动多个任务。多个视图共享任务时，某一个订阅取消仅解除它的回调；当无订阅且未被指定预热时，再按策略取消构建。

单次 worker 构建定期检查取消，特别是词法扫描与大数组归并。最新关注对象只保留一个待发布请求。构建完成不直接持有 `NSView` 或窗口；视图弱引用之外还要验证视图自己的订阅编号。

### 10.2 缓存预算

| 缓存 | 所有者 | 键 | 淘汰和释放 |
| --- | --- | --- | --- |
| Reader 派生数据 | 项目/阅读会话作用域的服务 | 分析身份 | 按估计成本 LRU；活跃读取者强持有 |
| 调用归属 | 对应 store/session | `ContentIndexKey` + store 作用域 | session/store 释放后可回收 |
| 投影元数据 | 每个 Reader | 内容与实际可见段版本 | 保留当前与事务所需旧版本 |
| 附件 | 每个 Reader | 当前占位实例 | 被移出投影后解绑 provider |
| 属性计算结果 | 每个 layout manager 的协调器 | 分析、投影、绘制修订及范围 | 有界容量；manager/文档切换清空 |
| 字体 | 已有字体解析器 | 已有请求与环境版本 | 沿用已有上限与刷新行为 |

派生缓存初始软预算可设为每项目 64 MiB，并提供测试配置注入；这是待 S0 校准的工程起点，不是已验证峰值承诺。大对象可以被调用者暂时持有而不进入 LRU；活跃对象超出软预算时停止预热并记录 `activeOverBudget`，不能无限驱逐重建。

成本估算包括自有数组、驻留名称、索引和临时构建空间。Swift 数组采用共享/COW 时，不能把每个引用都算成一份真实物理复制，也不能据此宣称所有桥接都零拷贝。分别记录逻辑拥有量与进程实际内存。[S2]

首批不引入全量源码 mmap 重构。工作区文件可以被外部写入，直接映射可变文件不自动等于不可变快照；现有捕获语义需要保留。

### 10.3 语义结果缓存边界

本文只规定静态 Reader 派生物和调用归属的复用。任何后续 Resolver/Exact 查询缓存都必须包含快照、analysis profile、provider/环境身份、查询参数和结果完整性语义；超时、取消、临时不可用不能永久缓存成“没有结果”。

同一份文件在不同项目配置下可以指向不同定义。内容复用不得掩盖这一点。

## 11. 可观测性与验收设计

### 11.1 计数必须放在真实工作点

| 指标 | 增加位置 | 用途 |
| --- | --- | --- |
| `identifierBuildCount` | 新倒排表实际开始构建 | 检查重复构建与合并 |
| `identifierScannedBytes` | 扫描器推进源字节 | 验证热查询无全文扫描 |
| `identifierLookupCount` / `returnedRangeCount` | 实际查询与返回切片 | 区分查询次数和结果大小 |
| `foldTopologyBuildCount` | 拓扑构建入口 | 检查文档级复用 |
| `callOwnershipBuildCount` / `queryRegionVisits` | 归属构建/查询 | 检查查询未退回嵌套扫描 |
| `decorationBuildCount` / `drawGlobalRecordVisits` | 派生装饰/绘制准备 | 暴露“只画可见区但先整理全文” |
| `projectionPlanBuildCount` | 纯投影构造 | 区分计划与物化 |
| `materializedUTF8Bytes` / `materializedUTF16Units` | 文本物化入口 | 验证小折叠没有重建全文 |
| `fullTextReplacementCount` / `partialTextReplacementCount` | storage 实际替换 | 区分字符更新方式 |
| `attributeUpdatedUTF16Units` / `paragraphRecordsVisited` | 实际属性/段落遍历 | 暴露局部 patch 后的全量属性工作 |
| `reflowRequestCount` / `reflowTransactionCount` | 请求/事务 | 观察合并效果 |
| `firstPaintMs` / `stableLayoutMs` / `longestMainThreadStallMs` | 原生观测点 | 区分函数返回、绘制和稳定布局 |
| `retainedDerivedBytes` / `peakPhysBytes` | 缓存估算/进程采样 | 区分缓存预算与实际内存 |
| `fallbackReason` / `cancelledStalePublishCount` | 回退与发布检查 | 检查错误路径和过期结果 |

已有 `projectionInstallCount`、段落与视口诊断计数保留原含义。新增计数不能通过重新定义旧计数使现有门禁“变绿”。可用一次交互前后快照取差值，避免多个窗口混合污染观测。

### 11.2 工作量门禁

以下断言限于已经完成分析、布局和显式预热的稳定场景。初次构建、真实字体变化和首次进入未布局区域应独立计数。

| 场景 | 必须满足 |
| --- | --- |
| 重复点击已经索引的标识符 | `identifierScannedBytes` 增量为 0 |
| 相同主题/设置重复应用 | 无新投影、无文本替换、无新的应用主动重排 |
| 仅变更颜色 | 无投影重建、无字符替换、无应用主动全量布局 |
| 稳定状态滚动/hover | 文档级装饰构建与全局记录遍历增量为 0 |
| 查询同一定义的外向调用 | 构建次数不增加，查询 region 全扫描为 0 |
| 关闭祖先内部调整子折叠 | 可见投影相同时，文本替换增量为 0 |
| 单个可见小函数折叠 | 未触发回退时无全量字符替换，物化量对应变化及段落上下文 |
| A→B→A 内容未变 | 缓存内命中复用；只有当前订阅发布 UI 状态 |

“无全量字符替换”与“无全量布局”是两个不同断言。不得用前者替代后者。

### 11.3 时间与内存评估

普通 CI 强制功能、数据完整性、工作量断言和任务结束。独占 macOS 性能验收固定构建模式、硬件、电源模式、OS、字体实际名称、语言、窗口与视口尺寸、fixture 哈希、预热条件及操作序列。[S7][S8]

保留现有 `run-fold-perf.sh` 的模式和预算；新场景单独记录，避免把不同条件拼成一个数。现有脚本的 `--enforce-budgets` 可以在专用验证中启用，不能声称普通 CI 已强制同样的耗时门槛。[S8]

新场景建议采用成组的基线/候选交替测量。每个版本至少 30 次有效样本；报告 p50、p95、最大值、物理内存峰值和样本数。对未作为优化目标的冷启动/切文件路径，默认警戒线为 p95 超过 `max(基线×1.10, 基线+2 ms)`，触发调查与书面裁决；该阈值是本计划建议，不是平台保证。

主要收益先由真实工作减少证实，再由时间测量确认。目标操作本来已非常快时，可以接受耗时近似不变，但必须展示工作量改善和整体无明显退化。

### 11.4 正确性覆盖

完整测试清单和编号见实施计划。最低覆盖集合包括 UTF-8/UTF-16 边界、组合字符、emoji、连字、CRLF/Unicode 换行、EOF、空文件、超长行、嵌套和异常折叠区间、重复名称与遮蔽、异步语法升级、A→B→A、外部刷新、主题+字体+wrap 同时变化、重复 provider 创建、多窗口关闭，以及原生复制/拖拽/VoiceOver。

原生验收包括主 Reader、Context、Compare 两列、Reading Set、普通文本与 Settings 预览。已有 HTML/PDF/图片预览做烟雾回归，检查设置传播没有破坏其独立策略。

## 12. 后续阅读投影与分块原型

### 12.1 触发条件

完成 A、B 后，若剩余延迟仍主要来自 TextKit 的大段落布局、远处 extent 收敛或全量 backing storage，则启动分块内容原型。官方 TextKit 提供内容管理和视口布局相关接口，但这并不证明自定义实现能自动满足 Cairn 的选择、无障碍、附件与性能要求。[A5][A6]

原型放在独立目录，复用真实 fixture 和测量方法。输出必须包含与现有后端的对比、能力缺口和采用成本。收益不稳定或关键交互缺失时暂缓产品接入。

### 12.2 分块布局原型的最小问题

验证按需提供文本元素/段落能否减少首次打开与大文件折叠的工作。记录全局高度估算、当前视口准确度、跨块选择、复制和查找命中。长单行分块还需要处理字形簇与行分割边界，不能直接按任意字节切片。

不得用“每行固定高度”覆盖现有混合字体、可变字重、连字、注释字体与软换行行为。任何近似只用于尚未显示的范围，并在进入视口时得到真实布局验证。

### 12.3 非文件顺序阅读投影

单文档投影之外，原型再引入以下来源类型：

```text
SourceSlice(snapshot, path, contentID, byteRange, instanceID)
FoldSummary(sourceRanges, summaryRuleVersion, instanceID)
GeneratedExplanation(sourceReferences, generatorIdentity, instanceID)
```

同一来源可以展示多次，所以源位置映射到一组显示实例。点击和返回优先选择当前实例及其阅读上下文；书签和外部跳转仍保存来源身份。

第一种建议原型是“一个函数及少量直接相关代码”的阅读组合。选择真实片段拼接，保留文件/版本/行号标签；不要求先实现通用 Canvas、图数据库或 Agent 项目识别框架。

### 12.4 复制和生成内容

跨片段复制默认按显示顺序导出用户选中的真实源码片段；跨文件边界提供明确分隔与来源信息。可增加明确命名的“复制源码”动作排除摘要/生成解释，但不能静默把两种复制语义混用。

生成解释有独立来源和生成信息。它可以帮助理解，但不写入原 `ReaderDocument.bytes`，不参与确定性符号索引，也不冒充仓库真实注释。逻辑骨架中隐藏的检查、日志和清理路径必须可展开查看，不能宣称变换后的片段与原程序执行语义等价。

## 13. 方案取舍与风险

| 风险/方案 | 本次决定 | 重新考虑的证据 |
| --- | --- | --- |
| 全量改写 Reader | 按现有入口逐阶段提取责任 | 只有适配层无法承载已验证需求时再扩大重构 |
| 自绘文本/完全替代 TextKit | 暂留原型阶段 | 原生测量显示显著且稳定收益，选择/AX/复制完整 |
| 将全部结果永久预计算 | 仅预计算稳定且反复查询的数据 | 使用数据表明新的高成本查询足够频繁 |
| 只靠颜色版本跳过系统 validator | 复用计算结果，遵守系统回调的属性提交要求 | 真实生命周期测试证明更强的有效性条件 |
| 任意局部替换保证 O(变化量) | 分别测量应用物化、storage 和布局传播 | 数据结构与后端均能证明该复杂度时再声明 |
| 为减少内存直接映射工作区文件 | 保持捕获语义 | 能证明映射内容不可外部变动且有完整生命周期 |
| 预先持久化全部新增索引 | 首批用内存派生物 | 冷启动与跨会话收益超过版本迁移成本 |
| 同一内容跨 store 共享 intern ID | 保留 store 边界或重绑定编号 | 有经过验证的跨 store 重编码协议 |
| 字体优化回退成手工宽度估计 | 复用字体解析与真实布局 | 只在明确限定的纯文本模式另行设计 |

主要实现风险是缓存键遗漏、框架回调观察到中间状态、旧任务覆盖新视图、局部 patch 后又执行全量段落扫描，以及把“估算 extent”当成“精确布局”。每项在配套计划中都有对应测试与回退入口。

## 14. 评审出口

评审需要确认以下工程约定：交付包 A/B 的范围；标识符保持现有默认匹配语义；派生数据异步就绪的界面策略；第一版投影仅支持单文档单调顺序；局部更新的完整选区行为；缓存软预算和专用性能环境。

未关闭的原生行为问题进入 S0 记录。它们不会被标记为“已解决”，也不能靠增大测试超时或删除断言获得通过。实施与发布的最终条件见配套计划的阶段出口和验收模板。
