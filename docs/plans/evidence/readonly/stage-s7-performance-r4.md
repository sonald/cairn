# S7 原生匹配性能验收（r4）

采集已完成：**6 个冻结 fixture × 2 个版本 × 30 次 = 360 个独立原生进程，180 个完整配对**。全部配置、选区、affinity 与命中结果可比；候选支持的稳定指标 1,320/1,320 通过，目标工作量检查无违规。

但这不是“所有门禁通过”：S0 Python 的 60 项真实稳定锚点失败被保留；**14 个相关冷路径 p95 指标触发警戒，尤其是 1 MiB 单段落的稳定等待尾延迟，尚不能由本轮测量免责**。原始 driver 以 exit 1 结束，原因是基线 Python 失败，非样本不足。冷警戒的审阅结论见下文。

## 身份、协议与可复现性

- S0：`4fdabe38eb364f9e9d7aa6507aa445fb636ad485`；候选：`62644e8c701185ffb9d7b6790563fd143877c58e`。候选是在 S6 `2c1bd4800f7ea68777ca2785ae8c318048720fe2` 上冻结两文件产品修复，非 root 用户分支的提前 S7 提交。
- 产品差异共 8 增 1 删：`firstVisibleByteOffset` 不再触发排版，显式导航恢复在写入口处理布局；AppDelegate 增加 CoreText distributed 字体通知注册/清理。完整 diff、tree SHA、两个源文件 SHA256 与封存 binary/resource hashes 随原始证据保存；两个产品源文件与最终 root 工作区逐字节一致。
- Mac15,6 / Apple M3 Pro / 36 GiB；macOS 27.0 (26A428)；Apple Swift 6.4 / macOS SDK 27.0；Release。开始、中途、结束均记录 AC；中途 `lowpowermode=0`、`sleep=0`。thermal/performance warning 查询不可用，不能声称锁频或排除温度影响。
- 每组 AB/BA 交替，fixture 顺序轮转；每次新进程，同一 Light/Aqua、字体/OpenType 请求、窗口与视口、源哈希。cold closure 在 display 后显式设置 caret 0，下游固定操作前的规范选区设置另行记录，不假设未初始化的 EOF caret 是用户意图。
- 首次实际绘制由 `drawBackground` 入口时间戳确认，不等于 compositor 上屏；稳定需真实 native turns、目标内容/属性/几何/选区一致、无 pending reflow、索引 ready，普通重排另验独立 fresh source anchor ≤1 pt。两版同样泵事件循环，另有共同 100 ms 内存观察；不以固定 sleep 宣称稳定。
- 物理峰值为 25 ms 定时采样的峰值；未做样本裁剪、均值替代或选择性重跑。p95 为 nearest rank，即 30 项中的第 29 项，不是置信上界。r1/r2 协议调试与 r3 被替代的部分候选数据均未混入本轮。

## 实际工作量

- 候选 180 个热查询场景：`identifierScannedBytes=0`；180 个滚动场景：`decorationBuildCount=drawGlobalRecordVisits=0`。
- 候选 180 个纯颜色场景：投影构建、全文替换、应用主动全文布局、段落访问、UTF-16 属性更新计数均为 0。
- 120 次合法 fold 与 120 次 unfold：全文替换均为 0，局部替换均为 1。Python 短函数与长行无合法 handle 不虚报动作。
- Rust/TS/TSX 单折叠的段落访问中位数由 997 降至 1，属性更新单位分别从 37,052/43,032/38,040 降至 1；这类折叠只插入占位符，源码 UTF-8 物化计数为 0，不能理解成零分配。应用局部替换也不等于框架保证局部布局。

## 冷警戒审阅

警戒线为候选 p95 超过 `max(S0 p95 × 1.10, S0 p95 + 2 ms)`。14 项是跨相同阶段的相关指标，涉及 5 个 fixture，不是 14 个独立故障。全部保留，未靠忽略尾样本使其通过。

1. **普通 Rust/Python/TSX**：警戒主要集中在首绘/端到端首绘尾部，Python display op p95 17.02→20.19 ms。配对中位 display 额外成本仅 0.47–0.88 ms；这些普通文件 cold-to-stable 的 p50 和 p95 都改善（TS 也改善且无冷警戒）。两版冷投影/替换/源码物化次数相同，候选另构建一次索引。证据支持“小幅首次准备开销换热查询复用”的解释，但不足以证明各尾部差异全由索引造成；警戒不能被改写为零回归。
2. **9k-line large**：cold stable 配对中位增加 24.93 ms，30/30 对更慢；候选多一次 313,962-byte 索引扫描，native readiness 通常需更多轮次。端到端 stable p95 2,957.26→3,386.16 ms，主要尾样本同时有更长 syntax preparation，而 preparation p50 2,538.53→2,525.73 ms。不能把约 429 ms 尾差全算为 worker 构建，也不能因 preparation 中位数改善就忽略尾部。
3. **1 MiB 单段落**：display op p95 5,262.74→4,971.24 ms 改善；first draw p95 10,776.06→12,800.00 ms，stable p95 14,589.36→23,513.20 ms 变差。stable 配对中位增加 1,915.22 ms，29/30 对更慢，前/后半程中位增量都约 1.9 s，不能只归为两个可删除异常。最慢候选样本 native turns 为 9–11，而 S0 为 4；真实工作计数没有新增全文布局、字符替换或源码物化，且采样物理峰值下降。现有协议未分开 worker 调度、额外原生生命周期工作和观察器成本，因此没有足够证据断言“索引本身耗费 2 s”或“只是噪声”。

**处置：样本采集、候选功能和目标工作量验证完成；本轮性能证据本身不清除冷路径警戒，尤其不为 1 MiB 单段落冷尾延迟背书。需要项目负责人明确接受已记录取舍，或另立不混样的归因测量。收集者未进行产品修改、阈值放宽或接受豁免。** 热查询和颜色收益是独立结果，不能自动抵消冷警戒。

## 真实失败与限制

- S0 Python 的 font-only、color-font-wrap 每项 30 次独立 fresh anchor 缺失，共 60 项 FAIL；候选对应 60 项全部 PASS。旧生产诊断曾给 error=0，但独立源锚点实际离开可见布局，故本报告不沿用该旧值当成功。
- 两版各 180 项高成本精确重排稳定指标为 NOT_RUN（large 与长行，各 3 阶段 × 30）。这以共同源成本阈值和真实 viewport readiness 为依据；操作/实际 draw 样本仍有效，未重试到 45 组制造精确恢复成功。
- 两版 Python 短 body 与长行各 30 次 fold/unfold 均明确不适用：没有 `hiddenLineCount≥2` 的可见 handle，不计成 no-op PASS。真实 Python fold 动作由 root 的额外 600-line 原生功能验收覆盖，非这组冻结性能输入。
- 本轮未做 10k/30k/50k/100k 各 30 对新匹配采集，不把已有规模功能/单次性能记录冒充足量统计；VoiceOver、跨应用真实操作与 S8 采用决策也不属于本文件的测量证明。
