M10 · Explainable Navigation — 界面原型 03（P0 探索，不进产品）

Reading Set — 把关系结果组织成连续可读材料

读一个符号时把「定义 + Verified 调用者 + Inferred 调用者 + trait + 测试」摊成一条连续阅读流——每段仍是真实源码，但带出处头（path:line · Verified/Inferred · commit · 查看证据）。这是它区别于 Zed multibuffer 的地方：只读、绑快照、带可信度。

固定 fixture：读 tokio spawn。对比两种布局，选一种在 M11 落地。

P0 定位：本原型只为选布局，不进 M10 产品（M10 只做 Evidence + Trail）。Reading Set 实现顺延 M11。
主题

我的倾向（供参考，最终你裁）

布局 B（Reading Set tab）是 Canvas 想要的形态，但它属于 M11。 理由：只有 B 能兑现「沿一条有证据的路径读懂一个符号」这个产品论点；A 的行内展开只是 peek，读不成连续材料。而 B 需要「非文件文档」原语（§2 已明确顺延 M11）。所以 P0 的结论应是：选 B 作为 M11 Reading Set 的目标形态，A 的行内 peek 可作为 Relations 的轻量补充另算。
  • 与 Trail 的衔接：Trail 浮层（C）里点某节点可「Open as Reading Set」，与 B 是同一个非文件文档原语——M11 一次性引入，两处复用。
  • 出处头是硬要求：每段的 Verified/Inferred + commit + 查看证据 不可省——这是 Cairn 区别于普通 multibuffer 的身份。「查看证据」直接开原型 01 的 Resolution Inspector。
  • 三主题都扫一眼：SI 暖纸下多个 excerpt 卡片叠加会不会太素、Dark 下卡片边界够不够分明。

若你认可「B 是目标形态、但 M10 不做」，那 P0 探索即收尾，M10 的三张核心原型（01 Inspector / 02+02b Trail / 本张定调）就齐了。
