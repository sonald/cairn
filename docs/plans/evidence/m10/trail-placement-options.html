Semantic Trail · 放置方案对比

同一份 trail（main → block_on → spawn ⑂ → LocalSet::spawn_local，spawn 分叉出 JoinSet 支）+ 同一段 reader 代码，放进 §3.11 的三种位置，直接比空间代价与分叉可读性。

主题

我的倾向（供参考，最终你裁）

A（顶部路径条）常驻 + C（浮层）唤出完整 DAG 的组合，而不是三选一。理由：日常阅读要的是「我从哪来、现在在哪」这条主线（A 永远在视野、几乎零成本）；只有在分叉/回溯时才需要整棵树（C 按需唤出、不长期占宽）。B 的常驻面板信息量最大，但和「不再增加固定工具表面」的取舍冲突（现已有 Reader/Context/Relations/Search）。
  • A 的分叉：主线 breadcrumb 上 spawn 带 ⑂ 2 支 chip，点开下拉列两支——轻量，但确认这个下拉够不够用。
  • C 的唤出键：⌘T 是示意，实际键位待定；也可由 A 上的 ⑂ 直接唤出 C，让两者衔接。
  • 若你更看重「分支始终可见」，则选 B 常驻面板，接受横向成本。

三主题都切一遍看：顶部条在 SI 暖纸下是否够清晰、浮层阴影在 Dark 下是否过重。
