Resolution Inspector + 三值 Evidence Badge

把 Core 早已算出、却在 GUI 被压成两个词的解释数据释放出来。左：Relations 列表的三值 badge 与折叠组；右：点行后的 Resolution Inspector。

色值全部复用 M9 S6 已上线的三主题 token；三值 badge 的绿/蓝复用 --grn/--blu，仅新增 Unresolved 的中性描边与 conflict 的琥珀 chip。

怎么读这个原型：点左侧任意关系行 → 右侧 Inspector 更新。特别看 Handle::spawn（陷阱行）、Future::poll（带修正轨迹的主行）、Show corrected candidates 三处——它们对应计划里最难的三条语义红线。切主题看三区是否协调。

设计决策（映射到冻结的 v1.3.1 计划）

  • 三值 badge 同通道 §3.4 / G0：Verified 绿填充、Inferred 蓝填充、Unresolved 中性描边——三者同占右上 badge 列，Unresolved 权重最弱但不再被塞进次级 modifier。
  • 目标位置正交 §3.7：dependency 是虚线 scope chip，不是第四个 epistemic 状态。external import 只诚实标「import binding」，不谎称已知外部实体。
  • 陷阱行不撒谎 §3.5 / E0：Handle::spawn 是 methodNameOnly + 结果集截断——默认行显 name match only、Inspector 显「result set truncated (500 of ~1,900)」，绝不显 Verified。这是「用户会不会把推断当精确」盲测要过的关。
  • conflict 修正双向可见 §3.8 阻塞3：主行 Future::poll（Verified）自己带修正轨迹「replaced Task::poll」；被修正的 Task::poll 折进 Show corrected candidates。点任一处都看得到这次冲突。
  • not-corroborated ≠ 否定 §3.3：Scheduler::schedule 的 exact 查询完成但未 corroborate，Inspector 中性陈述「does not prove it is absent」，仍显 Inferred。
  • SOURCE / VERIFICATION 两段 §1.6 / E3：来源推断与验证结果分列；corroborated 两段都在，verification-only 只有下段，conflict 下段变「VERIFICATION CONFLICT」。永不暗示「RA = 真值」§3.10。
  • 渐进披露 E3：badge → 一句「why」→ 「Show full audit」才露 resolver/certainty/dispatch/evidence/coverage/snapshot/profile。默认不倒给用户全部枚举。
  • Safe 限制不否定正向目标 §3.9：Safe 模式的 proc macros disabled 作为 limitation 明示，但不压制 RA 已返回的 Verified 目标。

待裁决 / 下一批原型
