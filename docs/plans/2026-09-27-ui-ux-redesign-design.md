# Cairn UI/UX 重设计 · 「勘测笔记本」

日期：2026-09-27
状态：设计方向已确认，未进入实施。
代码基线：`f5e116d`（`fix(reader): show complete functions and comments in Follow`）。文中关于现有实现的描述均以该提交为准。
设计稿：[Cairn UI Redesign 画布](https://claude.ai/artifact/T9x6o6qGmQbqMdx6sZVp2H)（私有，需分享后他人才能打开）。共 15 块画板，示例代码、调用关系与提交历史取自本机 `knuth-rs` 仓库的真实内容。
验证状态：画板 HTML 只做过标签闭合检查，**尚未在浏览器中逐块目检渲染**。

## 1. 为什么要重设计

现有界面（`docs/reviews/evidence/2026-09-11-product-polish/final/`）的问题：

- 视觉粗糙、通用：系统默认控件 + 紫色强调按钮，看不出这是一个「代码阅读器」，也看不出与 Source Insight 的渊源。
- 信息平铺，没有层次：所有状态同等音量；Relations、Inspector、Trail 用大量等宽小字和全大写标签堆叠。
- 产品真正的差异化（`docs/design.md` §0 的五条）在界面上不可见：
  确定性 / 证据体系、历史快照、Safe 模式都只以一行状态栏文字出现。
- Source Insight 式的排版层次（函数名放大加粗）实际默认关闭（见 §4.3）。

## 2. 设计方向

**「勘测笔记本」**：Cairn 是在陌生地形里堆起的石头路标。界面把阅读陌生代码当作一次野外勘测：石色纸面、野外手册式衬线字、每个答案都标注「有多确定」。

三条原则：

1. **排版层次优先于颜色**（继承 Source Insight）：结构靠字号与字重读出来，颜色只承担语义。
2. **语义色固定，不做装饰**：苔绿 = 已验证 / 当前作用域 / 主操作；琥珀 = 你在这里（当前位置、书签、信任）；石板蓝 = 推断；锈红 = 未解析 / 破坏性；褐黄 = 历史。
3. **诚实默认**：任何面板都说明「知道什么、怎么知道的、缺什么」，不出现空白面板或单一百分比（呼应 §14 覆盖状态分项展示）。

### 3.3 Source Insight 式声明层次

| 级别 | 元素 | 处理（Granite / Basalt） | SI Classic |
|---|---|---|---|
| 1 | 函数 / 方法定义名（含 trait 方法签名） | +4.5pt（17.3px），粗体 | +5.5pt，粗体 |
| 2 | 类型定义名：struct / enum / trait / type，impl 头里的类型 | +2pt，半粗，类型色 | +2.5pt，粗体 |
| 3 | 局部声明（let 绑定、签名参数） | 同字号，半粗；后续使用按「参数透明度」变淡 | 同左 |
| 4 | 项目内函数调用 | 字重 500；依赖 / 标准库调用保持常规 | 同左 |

### 3.4 确定性标记：堆石

整套界面唯一的招牌图形。0–4 块叠放的小石头表达 `Certainty`：

| 石数 | Certainty | 含义 |
|---|---|---|
| 4 | Exact | 精确 provider 或可证明唯一的绑定 |
| 3 | Strong | 最佳启发式：作用域、import、receiver type |
| 2 | Probable | 排序候选，排在 Possible 前 |
| 1 | Possible | 仅名字匹配，折叠到「Show N possible matches」 |
| 0（虚线） | Unresolved | 未找到目标，明确说出来 |

标签语法沿用 §4.2：`certainty · dispatch · provenance · completeness`，例如 `Exact · via trait Write`、`Strong · direct`、`Possible · dynamic receiver`、`Partial · generated by macro`。行级徽章沿用 M8 裁决的 `Verified` / `Inferred`，不按 certainty 分组。

### 3.5 其他组件

- **徽章**：Verified、Inferred、Unresolved（描边）、Corrected、dispatch（等宽描边）、dependency、worktree · captured、commit 哈希（褐黄）、limited（琥珀）。
- **信任印章**：Safe（苔绿盾牌）/ Trusted（琥珀盾牌），常驻标题栏。
- **符号种类**：`fn` / `st` / `tr` / `im` / `en` / `md` 小色块，用于大纲、Seek、Relations 根。
- **Gutter 词汇**：书签旗、diff 条（改 / 增 / 删）、折叠箭头、**作用域竖线**（当前作用域范围的淡色竖线）、主选中（苔绿描边 + 淡填充，即 M9 S2 Variant B）、occurrence 底色。

## 4. 行高：沿用现有机制

### 4.1 现有实现

- 阅读区行高只由段落样式的 `lineHeightMultiple` 决定（`CodeInsightReaderUI.swift:3677`），默认 1.3（`ReaderSettings.swift:114`）。没有设置 `minimumLineHeight` / `maximumLineHeight`。
- 因此每行高度 = 该行最高字形的自然行高 × 1.3。函数名放大时，所在行自然变高。

### 4.2 结论

不引入固定行高，也不为定义行做特殊段落样式。定义行变高本身就是 Source Insight 式的「标题行」效果，用户已确认视觉可接受。设计稿按此模拟：正文行约 21px，函数定义行约 28px，类型定义行约 24px。

### 4.3 需要调整的默认值与范围

| 项 | 现状 | 目标 |
|---|---|---|
| `functionNameDelta` 默认值 | `0`（`ReaderSettings.swift:116`），比 M1 计划的 +1pt 更保守 | 约 4.5 |
| `functionNameDeltaRange` | `0.0...4.0`（`ReaderSettings.swift:56`） | 放宽到约 `0.0...8.0` |
| 类型定义字号 | `.functionName` 与 `.declarationTitle` 共用一个分支和字号（`CodeInsightReaderUI.swift:3936`） | 新增独立的类型名增量，默认约 +2 |
| 散文注释 | `humanistComments` 默认关，打开后用系统无衬线字体（`CodeInsightReaderUI.swift:3955`） | 待定：是否改用衬线斜体、是否默认开启（§8） |
| 默认行高 | 代码 1.3，`docs/design.md` §9.2 写 1.25 定案 | 需统一其一 |

M0-B 探针关于可变字号成本的结论（§9.2）依然适用：字号是 layout 属性，仅作用于定义名 span，验收时需复测巨档文件首屏与内存。

## 5. 界面结构

### 5.1 主窗口

```
┌ 标题栏 ────────────────────────────────────────────────────────────────┐
│ ●●● ‹ › [石]knuth-rs  [⎇ main ─•─•─•─◉ Working Tree ▾]  [⌕ Seek… ⌘P]  │
│                            [RS knuth-agent · default · 2021 ▾] [Safe] [预设] ⚙ │
├ 侧栏 ───────┬ 标签页 ─────────────────────────────┬ Relations ─────────┤
│ Files       │ 路径 › 作用域      [Trail ●─●─●─◉] [Full|Structure|Overview] │
│ Outline     │                                     │ 根：spawn_actor    │
│ Current     │           阅读区                     │ Callers|Calls|Impls|Refs │
│ scope 卡片  │                                     │ 行：堆石 名称 path:line dispatch 徽章 │
│             │                                     │ [Freeze] [Inspector ⌘I] │
├─────────────┴ Lens ───────────────────────────────┴────────────────────┤
│ Follow|Pin  符号名  候选列表(1/4…)  │  候选摘录 + 确定性 + 来源 + DocumentID │
├ 状态栏：Files ▮ · Imports ▮ · Exact ▮ ready·limited · 堆石 Query complete   Ln/Col ┤
```

- **时间轴**：替代原「⎇ main · Working Tree」，显示提交刻度与当前位置；点击打开提交选择器。
- **Seek**：合并 ⌘P 文件、⌘T 符号与命令面板为一个入口，前缀 `>` `@` `#` `:` 切换模式（待定，§8）。
- **Trail 迷你条**：在路径栏右侧显示最近几站，当前站为琥珀点。
- **Lens**（即 Context Window）：底部横跨阅读区与 Relations。左栏为 Follow / Pin、Lens 内前进后退、符号名、候选列表；右栏为选中候选的摘录。Pin 时显示「Pinned · clicks update Relations only」（F2.3）。
- **状态栏分层**：Files / Imports / Exact / 当前查询完整度各一条，不压成单一百分比。

### 5.2 历史快照与对比

- 切到历史 commit 时，阅读区整体使用褐黄 `histReader` 底色，标题显示「read-only snapshot · worktree untouched」。
- 提交选择器：搜索、分支 / Tags 切换、每条提交标注「Exact cached」（已物化）；底部说明「Fuzzy 在任何提交都可用；Exact 需物化，2 GB 缓存」。
- 对比视图：顶部「Changed functions」条（Body / Added / Removed · 符号名），hunk 导航，左右对齐 diff，缺失侧用斜线填充。
- 未物化快照的状态栏写明「fuzzy only · queries capped at Strong」。

## 7. 实施映射（未开始）

以下只列出落点，具体拆分另立实施计划：

1. **主题 token**：在现有 `ReaderTheme` 增加三主题 surface 与语义色，沿用 M9 S6「不建应用级主题系统」的约束。
2. **声明层次**：§4.3 的默认值、范围与独立类型字号。
3. **堆石标记与徽章**：新增一个共享绘制组件，替换 Relations、Lens、Reading Set、Trail、状态栏里的文字 certainty。
4. **标题栏**：时间轴、Seek、Profile 芯片、信任印章、布局预设。
5. **Lens 版式**：左候选栏 + 右摘录。
6. **历史着色**：历史快照阅读面使用 `hist*` token。
7. **状态栏分层**。

每项 UI 改动按仓库约定在原生应用中实测验收，并附截图。
