# Cairn 编程连字支持：需求说明

日期：2026-09-22  
版本：1.0，评审稿  
代码基线：`sonald/cairn@d1f68eee3300df8525ce914b2fb37760c82c65a3`  
状态：功能实现已落地，发布验收进行中；实际通过项、性能结果与阻塞见[验收记录](2026-09-22-reader-ligatures-acceptance.md)。

配套文档：[技术设计](2026-09-22-reader-ligatures-design.md) · [实施计划](2026-09-22-reader-ligatures-implementation-plan.md)

## 1. 目标与背景

让用户在 Cairn 的代码阅读面选择已安装的代码字体，控制编程连字，并继续准确地选择、搜索、复制、导航和折叠源码。例如，`!=`、`->`、`=>` 可以采用字体提供的连接形态显示；复制出来的内容仍为原来的字符序列。

本次开发以现有 AppKit / TextKit 2 阅读器为基础。TextKit 2 负责字形成形与排版，Cairn 负责字体策略、源码范围和阅读交互。Apple 将字符与字形的复杂关系封装在 TextKit 2 中；Fira Code 官方将编程连字描述为字体渲染功能。[^textkit][^firacode]

### 1.1 本版核对后的现状

本次基线已包含 9 月 22 日的 wrap 工作。以下能力已经存在，实施时直接扩展：

| 已有能力 | 本次接入点 |
| --- | --- |
| `ReaderViewportState` 保存源锚点、完整选区数组、affinity、水平位置和投影版本 | 字体和连字变化进入相同的重排生命周期 |
| `ReaderViewportGeometry.visibleRects` 返回可见文本片段矩形 | 增加连字部分选择和 Unicode 回归用例 |
| `ReaderTextView.apply(settings:)` 对相同设置提前返回；纯几何变化复用投影 | 将字体特性纳入相等判断和排版变化判断 |
| Reading Set 已使用 TextKit 2，以实际排版计算片段尺寸 | 测量签名加入字体身份、特性及字体环境版本 |
| `ReaderParagraphLayout` 统一计算前导空白与悬挂缩进 | 度量使用最终解析的代码字体 |

这些结论来自当前源码。较早一轮讨论中提出的“新增完整选区快照”“新增多矩形高亮”“改造 Reading Set 为实际布局测量”，在当前基线已具有实现，具体效果仍需通过本功能的组合测试确认。[^reader][^viewport][^readingset][^paragraph]

## 2. 用户场景

**切换熟悉的编程字体。** 用户安装了带连字的等宽字体，在 Settings 的 Reader 页面选择它，预览显示连接形态；主 Reader、对比 Reader 和代码摘录采用同一字体策略。

**检查精确的源码字符。** 用户看到 `!==`，关闭连字检查其原始组成，再开启连字继续阅读。其选区、搜索命中和复制内容保持准确。

**在代码中间调整阅读样式。** 用户正在一个折行函数中阅读，改变字体、字号或连字模式，阅读器保留当前选区，并按既有重排规则恢复可见位置。

**查看冻结的 Reading Set。** 用户打开多个代码摘录后切换字体。卡片根据新字体重新排版，行号与实际视觉行对齐，外层阅读位置遵循现有卡片锚点规则。

## 3. 首版范围与阅读面策略

首版提供一个全局代码字体选择和一个三态连字设置。初始默认值为“系统等宽字体 + 跟随字体默认”。字体由用户的系统字体环境提供。

| 阅读面 | 首版策略 | 验收责任 |
| --- | --- | --- |
| 主 Reader、对比 Reader、Context 等使用 `ReaderTextView` 的代码面 | 应用全局代码字体与连字模式 | 逐个确认首次创建和实时更新 |
| Settings 代码预览 | 应用相同配置，展示固定操作符样例 | 预览与实际 Reader 一致 |
| Reading Set 代码卡片 | 应用相同代码字体策略，按真实布局重新测量 | 卡片选区、尺寸及外层锚点 |
| 字符串和使用代码字体的注释 | 随代码字体应用连字模式 | 源文本与复制结果准确 |
| `humanistComments` 注释 | 保留其独立字体策略，采用该字体的正常文字成形 | 代码字体特性不能残留到这类注释 |
| 行号、折叠 chip、路径标签与普通 UI 文本 | 沿用各自的 UI 字体策略 | 代码正文变化后位置和尺寸正确 |
| 普通文本、Markdown 渲染、HTML、PDF、图片预览 | 采用各自现有排版策略 | 验证全局广播不会误应用代码字体 |

首版范围不包含字体安装器、字体文件分发、逐操作符开关、任意 OpenType feature 编辑器、按语言覆盖设置、光标进入后自动拆开连字，以及新增编辑能力。上述项目进入后续需求池。

## 4. 功能需求

### R01 字体选择与恢复默认

Settings → Reader 增加 `Code Font` 选择器，提供 `System Monospaced` 和已安装的候选代码字体。列表优先展示等宽字体，字体候选与实际可用性由平台层确认。显示名称供人阅读，持久化身份采用 PostScript name。

系统默认字体使用专门的配置值，避免将系统当前返回的字体名称固化为默认值。切换回系统默认后恢复对应的默认解析策略。

### R02 连字三态

新增 `Programming Ligatures`：`Font Default`、`On`、`Off`。

| 值 | 用户可观察行为 |
| --- | --- |
| Font Default | 使用当前字体的默认可选成形行为 |
| On | 请求启用本版本支持的编程连字相关特性 |
| Off | 请求关闭这些可选连接形态；支持字体上的样例恢复为分离形态 |

字体未提供某一连接形态时，On 可以没有视觉变化。界面必须允许用户看到预览，并说明“是否有连接形态取决于字体”；不能仅因设置保存为 On 就宣称字体已生效。

Apple 的普通 `.ligature` 属性与字体的 OpenType 特性需要结合处理，Fira Code 的编程连接形态涉及 `calt`。实施策略见设计 D03。[^attributes][^firacode]

### R03 全局传播与幂等更新

通过既有应用级 ReaderSettings 提交链路保存和广播设置。已打开窗口、之后创建的窗口和 Settings 预览收到同一个有效设置值。

相同设置且字体环境未变化时，重复 apply 不创建新投影、不写文本排版属性、不启动额外重排。字体安装环境变化是独立的失效条件。

### R04 样式派生一致

正文、放大的函数名、加粗声明和代码字体注释共享同一字体来源。字号和字重派生后保留相应连字特性。目标字重缺失时，优先在同一字体族内降级，并记录实际选择。

`syntaxFormatting = false` 时，代码字体和连字设置仍生效。函数名强调和 humanist 注释行为按原有开关组合执行，清理前一次模式留下的属性。

### R05 源码与范围完整性

字体及连字变化前后，源字节、`ContentID`、源行表、显示字符串及其 UTF-16 长度保持一致。搜索、导航、书签、符号引用继续基于原有源范围。

复制经过现有源文本映射路径；不能把视觉上类似 `≠` 的形态复制为 Unicode 替换字符。测试同时覆盖部分连字选区与跨折叠占位符选区。`DisplayMap` 继续管理源字节与显示 UTF-16 的投影。[^displaymap]

### R06 原生选择与精确复制

在已验证的字体组合上，用户可以用系统支持的选择手势、键盘扩选和查找定位原始字符范围。测试 `!=` 中的 `=`、`!==` 中的子范围以及相邻普通字符，确保最终选区和复制内容正确。

鼠标命中和 caret 停靠采用原生文本系统的行为。发布记录说明测试字体上的行为；若原生行为使必要的源码子范围无法通过任何常规操作选中，该字体组合不能列为已验证支持。

### R07 搜索与视觉强调

查找命中可以只覆盖连字中的部分字符；数据范围保持精确，视觉矩形由 TextKit 的实际文本段几何决定。全字形或局部覆盖的原生表现要记录，禁止按字符数平均分割字形宽度推测选择框。

新增高亮、当前命中框和颜色变化不主动切换字体特性。跨颜色边界的操作符、函数名大小变化和 wrap 组合列入验证。

### R08 重排与阅读状态

连字、字体和影响字体度量的样式变化复用已有重排状态。保留完整选区、原生 selection affinity、查找当前项、当前行、折叠状态及水平位置。

普通文件按现有源锚点和视口偏移恢复。当前实现对超过 8,000 个源行的文件限制同步视口恢复，本需求保留该性能保护；选区恢复必须独立于是否执行同步视口矫正。大文件状态使用单独的验收标准，不能标记为已达到普通文件的像素锚点精度。[^reader]

### R09 Reading Set 尺寸与缓存

字体切换、连字切换、字体实际回退结果变化后，卡片必须重新测量。采用相同配置重复 apply 时可以复用结果。

卡片正文、测量和段落缩进使用同一份解析字体；各卡片更新后通过现有外层重排机制恢复阅读位置，避免每张卡片独立修改外层滚动条。

### R10 配置持久化与迁移

缺少新增 key 的旧配置按默认值读取。未知连字枚举回退至 Font Default；已保存但暂不可用的字体身份仍予保留，实际显示采用系统回退，并给出可理解的提示。

配置保存必须覆盖 `ReaderSettings.save(to:)` 内部的校验重构造路径。字体显示名、NSFont 实例与运行时缓存均不写入 UserDefaults。[^settings]

### R11 字体能力与回退反馈

区分用户请求的字体、实际解析字体、目标字重是否回退、连字验证状态。字体 feature 列表只作为能力线索；确定“已验证支持”需要固定样例的实际成形与 Reader 交互证据。

首版至少验证一套带编程连字的字体及系统回退行为。第二套字体作为交叉验证对象。字体版本与测试环境必须记录。

### R12 生命周期与资源边界

字体对象与测量对象由 UI 层管理；Core 类型保持 Foundation 值模型。字体查询和缓存有界，窗口关闭后不因本功能残留文本视图或订阅。相同设置遇到字体环境变化时能够重新解析。

## 5. 性能与质量要求

以下数字是本方案提出的目标，尚无本功能实测结果。P0 需在固定机器、字体版本和 fixture 上记录基线并评审预算；调整预算须保留原目标、测量证据和理由。

| 编号 | 指标与初始目标 | 测量方式 |
| --- | --- | --- |
| N01 | 相同有效配置重复 apply：projection install、字体属性更新、主动重排计数均为 0 | 预热后读取增量计数；系统自发绘制单独记录 |
| N02 | 纯字体／连字切换：源码投影重建和全文字符串替换为 0 | 单独区分投影安装与 attributed attributes 更新 |
| N03 | 约 2,000 行常规 fixture：切换至首个正确帧 p95 目标 ≤ 300 ms；稳定目标 ≤ 1 s | release 构建、预热后至少 30 次，真实绘制确认 |
| N04 | 同字体 On 对 Off 的稳定滚动 p95：目标 ≤ `max(1.2 × Off, Off + 2 ms)` | 相同窗口、滚动脚本与文件，单独报告每帧时间 |
| N05 | 大文件、超长单行、Reading Set 沿用现有 wrap fixture 与预算方法 | 记录首帧、稳定、主线程阻塞与峰值内存，不套用常规文件结论 |
| N06 | 连续切换 100 次后：缓存条目受上限约束，无随切换次数线性增长的存活文本对象 | 记录缓存规模、对象生命周期和静止后的内存走势 |
| N07 | UI 不出现残缺字形、截断正文、错误复制或跨文件延迟恢复 | 原生截图与自动化状态断言结合 |

首帧必须同时满足“正确字体、正确 feature、正确当前文件”，仅出现一次 draw 回调不算完成。大文件结果出现降级时应明确标注。

## 7. 发布标准

发布前须具备：至少一套固定版本字体的原生成形证据、A01—A15 的结果记录、所有受支持代码面的截图与复制验证，以及通过的现有 CI 和冻结后的性能门槛。

遇到问题时，用户可回到系统等宽字体与 Font Default。兼容性说明应列出字体版本、macOS / SDK 环境、已验证范围和已知的大文件恢复限制。
