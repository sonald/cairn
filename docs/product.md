# 产品行为与边界

Cairn 是 macOS 原生只读代码阅读器；CodeInsight 是 Swift package 和模块名。它帮助用户阅读陌生项目、理解符号与关系、比较 Git 快照，并保留阅读现场。当前语言分析支持 Rust、Python、TypeScript/TSX、Go。

## 只读与分析信任

Cairn 不编辑源码，不改动用户工作区与仓库（不写 HEAD、索引或 `.git/` 中任何内容），也不替项目安装依赖。索引、搜索、上下文、AI 工具与比较读取捕获时的工作区内容或 Git 对象：工作区文件在捕获后变化或被删除时，这些功能把它报告为已变化（来自索引的跳转不落地并提示刷新索引），不会把新内容当作捕获的内容。在工作区模式下从文件树直接打开文件，阅读区显示的是磁盘上的当前内容；已删除的文件显示“无法打开”。远端目录（见“远端目录（ssh）”）同样如此，显示的是远端文件当前的内容。切换历史不会改变工作区。

历史 commit 的精确分析在应用自有的检出目录中进行。检出目录在 `~/Library/Application Support/CodeInsight/checkouts/` 下，每个窗口一份，是一个通过 alternates 读取用户仓库对象的独立仓库，用户新提交的 commit 无需同步即可检出。只落盘普通文件，符号链接与 gitlink 不检出；换行、ident、filter 转换全部关闭，落盘字节与阅读区显示的 Git 对象一致。关窗即删除；启动时删除不属于任何活动窗口的残留目录；设置中的“清除检出目录”先停止所有窗口的精确分析再删除，并显示目录总大小。用户仓库 gc 后旧 commit 不可达时检出失败，精确分析报不可用，阅读不受影响。

切换 commit 或回到工作区时，语言服务器尽量原地跟随而不重启。条件是项目、分析单元、语言、特性选择、信任模式、Python 解释器与是否借用工作区依赖都不变，Python 的 `uv.lock`、TypeScript 的 `bun.lockb` 也不变；配置文件内容（`Cargo.toml`、`pyproject.toml`/`pyrightconfig.json`、`tsconfig.json`/`package.json`、`go.mod`/`go.work`）与 Rust 的 `Cargo.lock`、Go 的 `go.sum`/`go.work.sum` 变化由服务器自己重载，不算变化。跟随的顺序是：暂停新请求、取消在途请求、关闭已打开的文档、检出目标 commit、通知变化的文件，等服务器确认吸收后才恢复回答；任一条件变化或确认失败则换一个新会话冷启动。原地跟随不重新检查语言服务器版本，升级后的服务器在下次冷启动时生效。每个窗口为工作区与检出目录各保留一个会话，切换只改变当前用哪一个；另一个待命，待命超过 10 分钟或其服务器进程的物理内存占用（含被压缩的内存）超过 2 GB 时关闭，下次使用时冷启动。冷启动的 rust-analyzer 在加载工作区期间，状态栏显示“准备中”，首次报告 quiescent 后才显示“就绪”；加载期间的请求照常发出，服务器加载完再回答。gopls 冷启动在加载工作区（`$/progress`“Setting up workspace”）期间显示“准备中”，期间的请求等加载结束才发出，最多等 300 s，不受单个请求的超时限制；启动 5 s 内没有开始加载即视为就绪；gopls 热切换不等待，切换后第一个请求就是新答案。TypeScript 与 Pyright 没有启动加载信号，启动后即显示就绪。热切换与回到待命槽时，已加载的服务器直接显示就绪。

Exact 分析由本机安装的 rust-analyzer、Pyright、typescript-language-server、gopls 提供。默认 Safe 模式禁止网络，Rust 构建脚本和 proc macros 关闭；Go 的 cgo 保持开启（关掉会让含 `import "C"` 的文件整个退出分析），gopls 以 `GOTOOLCHAIN=local`、`GOPROXY=off` 运行，构建与 gopls 缓存写在分析缓存里。依赖只取本机已有的，按语言处理：

- Rust：依赖来自 `~/.cargo`，不借用；本机 registry 缺少锁定版本时标注“缺少本机依赖”。
- Python：工作区与 commit 都告诉 Pyright 使用工作区分析单元根下 `.venv`/`venv` 的解释器；没有时 Pyright 自己在 PATH 中找，并标注“缺少本机依赖”。commit 自己配置了相对 `venvPath` 时，检出目录同时以符号链接借用工作区的该目录。
- Go：依赖来自本机 Go 模块缓存（`go env GOMODCACHE`），不借用；仓库自带 `vendor/` 时 gopls 直接用它。缺少某个模块时分两种：连它的 `go.mod` 都不在缓存里时，`go list` 可能整体失败，整个单元的精确分析都不可用（实测 `go 1.15` 的 cobra）；`go.mod` 在、只缺源码，或模块较新（实测 `go 1.20` 的 viper 与 `go 1.22` 的模块）时，单元照常加载，只有导入缺失模块的位置报错。两种都标注“缺少本机依赖”，后者按 gopls 的 “no required module provides package” 诊断识别，所以代码导入了 `go.mod` 没有声明的模块时也会这样标注。`go.mod` 要求比本机更新的 Go 时，精确分析不可用并显示 go 的原话（如 `go.mod requires go >= 1.99 (running go 1.27.3; GOTOOLCHAIN=local)`）。
- TypeScript：工作区中存在、且位于项目根或目标 commit 中某个 `package.json` 旁的每个 `node_modules`，以符号链接放到检出目录同一位置。工作区模式下分析单元根及其所有上级目录都没有 `node_modules` 时（与 Node 的解析一致，monorepo 子包用根目录的安装）标注“缺少本机依赖”。

commit 分析借用了工作区依赖时标注“依赖来自当前工作区，可能与该 commit 不一致”。借用链接每次检出重算，与该 commit 跟踪的路径冲突时以 commit 内容为准；借用的目录对语言服务器只读。跳到依赖中的 `.d.ts`、`.pyi` 声明文件时按 TypeScript、Python 只读打开与高亮（多数 npm 包只发布声明文件）；它们不计入项目语言探测与源码计数。依赖文件标签页按绝对路径保存，重启后从磁盘恢复。缺少工具、本机依赖或沙箱时仍可语法阅读，并明确显示精确分析不可用的原因。

缺少本机依赖时，状态栏显示“精确分析：就绪 · 缺少本机依赖”，标签可点击；每个窗口对每个分析单元第一次出现该标注时，若窗口在前台且没有其他弹出内容，约 1.5 秒后自动弹出一次说明气泡（窗口当时不在前台则在它回到前台时弹出），之后只在点击状态标签或 ⓘ 时出现。气泡给出缺什么、安装命令及其运行目录（可复制）和一个动作：

- Rust 且能向上找到 `Cargo.lock`：“下载依赖”在分析沙箱之外运行 `cargo fetch --locked`（命令在分析单元目录执行；commit 模式用检出目录，即该 commit 的锁文件）。除 AI 提问、保存了 Jev 密钥时的概览评分和用户打开的远端目录（ssh）外，这是 Cairn 唯一的联网，只在这一点击时发生，与信任模式无关；它只写 `~/.cargo`，不运行项目代码，不改动仓库。下载中状态栏显示“正在下载依赖”，可取消；失败显示 cargo 最后一行错误并可重试；成功后冷启动语言服务器（不沿用待命会话，否则旧会话保留原来的 crate 图与“缺少本机依赖”标注）。重启后若仍标注缺依赖，气泡不再提供下载，只说明剩余缺口多半来自 Rust 标准库自身的依赖。没有 `Cargo.lock` 时 `cargo fetch` 会新建锁文件，所以只给命令、不代为执行。
- Go 且单元有 `go.sum`、没有 `vendor/`：“下载依赖”在沙箱之外运行 `go mod download`，与 Rust 一样只在这一点击时联网、可取消、失败显示 go 最后一行错误、成功后冷启动。为了不改动仓库，它把 `go.mod`/`go.sum` 复制到仓库外的临时目录，以 `-modfile` 指向副本运行（`go.sum` 不完整时 go 会补写的是副本）；`go.work` 单元对 `use` 列出的每个模块分别以 `GOWORK=off` 运行。commit 模式用检出目录，即该 commit 的 `go.sum`。没有 `go.sum`（`go.work` 单元里任一模块没有）时只给命令、不代为执行。仓库自己的 `go.sum` 不完整时下载补不上：go 需要写仓库里的 `go.sum`/`go.work.sum`，沙箱拒绝；重启后仍标注缺依赖时，气泡不再提供下载，改为说明 `go.sum` 可能不完整或代码导入了未声明的模块。
- TypeScript：按最近的锁文件选 `pnpm install`、`yarn install`、`bun install` 或 `npm install`，在锁文件所在目录运行；Python：按单元根的 `uv.lock`、`poetry.lock`（虚拟环境放进项目）、`requirements.txt` 依次给出命令，否则建 `.venv` 并 `pip install -e .`。这些安装会运行包脚本并写入仓库，所以按钮只复制命令并在该目录打开“终端”。应用重新回到前台时，若单元已出现 `node_modules` 或可用的虚拟环境，自动重启分析。

语言服务器在沙箱中运行。Safe 与 Trusted 都禁止网络；检出目录、借用的依赖目录、用户源码与 `.git` 不可写，只允许写分析缓存。会话长驻、跨 commit 复用，所以不设累计 CPU 时间上限，单次请求超时、崩溃重启与虚拟内存上限保留。沙箱拒绝文件系统事件服务，rust-analyzer 因此没有自己的文件监视（S0 实测），切换带来的变化由 Cairn 逐个通知。用户显式信任项目后，Rust 分析可以开启构建脚本/proc macros，并允许写项目 `target` 目录，网络仍关闭。因此“只读”不是承诺所有受信任分析子进程完全没有写入。撤销信任会停止并重建受影响项目的分析；清理检出目录前停止所有窗口的 Exact 工作。

打开远端目录时，Cairn 用系统的 `/usr/bin/ssh` 连接用户指定的主机，只在这个项目的窗口开着时保持连接。只读承诺对远端同样成立：Cairn 运行的脚本经 ssh 的标准输入送过去执行，不在远端写任何文件，只列目录、读文件、算哈希和压缩输出，不运行会写仓库的命令（包括会重写 Git 索引的 `git status`）。

本机 Dash 服务（127.0.0.1 上的 Dash API 与它的文档服务器）不算外网，Safe 与 Trusted 模式下都可用：文档面板只连 loopback，页面脚本关闭，页面引用的外部资源被内容规则拦截。

## 项目、快照与窗口

- 打开项目（菜单、最近项目、拖放、Retry、会话恢复）不询问语言。语言由捕获工作区时的文件后缀探测：`.rs` 为 Rust，`.py` 为 Python，`.ts`（不含 `.d.ts`、`.mts`、`.cts`）与 `.tsx` 为 TypeScript，`.go`（含 `_test.go`）为 Go；与文件树共用同一次遍历和排除规则，没有条目上限。单语言只是其中一种情形。没有任何受支持源码的目录（如纯 C/C++、Java 仓库）以只浏览方式打开：文件树、预览、commit 切换和刷新照常可用；项目符号、关系、上下文、项目搜索（输入查询后）和 `#` 符号查找显示“仅浏览：没有可分析的 Rust、Python、TypeScript、Go 源码”，状态栏精确分析显示不可用并给出同一原因。打开文件后按非源码预览布局只保留文件与项目符号面板。只浏览项目不提供版本比较，也不写入阅读会话，重新启动不会恢复它；刷新后出现受支持源码即转为正常分析。状态栏分析配置菜单逐个分析单元列出语言、源码文件数和单元根；最近项目只记录路径。
- 语言集合在捕获工作区时确定：首次打开，以及停在工作区时的 Refresh Index 与保存排除规则（停在 commit 时它们重新捕获该 commit，不改变集合）。切到 commit 沿用当前集合：commit 缺少的语言保留空索引，多出的语言只预览；切回工作区不重新探测。Refresh Index 失败时连同集合恢复。重新打开或恢复会话总是重新探测工作区，会话里保存的语言不再使用；因此恢复一个停在旧 commit 的会话时，工作区已不再包含的语言在该 commit 中只预览。
- 每门语言按 marker 目录（Rust `Cargo.toml`，Python `pyproject.toml` 或 `pyrightconfig.json`，TypeScript `tsconfig.json`，Go `go.mod` 或 `go.work`）划分分析单元。该语言在当前快照里没有源码时（如 commit 中缺少这门语言），保留一个项目根的空单元。没有 marker，或有 marker 目录包含该语言全部源码时，只有一个单元：根为包含全部源码的最浅 marker 目录，没有 marker 时为项目根；带根 workspace 清单的仓库因此仍是一个单元。其余情形（如没有 workspace 的多个 crate、多个互不包含的 `pyproject.toml`、`tsconfig.json` 或没有 `go.work` 的多个 `go.mod`）按 marker 拆分：每个源码文件归入包含它的最深 marker 目录，没有 marker 祖先的源码归入项目根单元，嵌套单元里的文件不属于外层单元。选中文件时状态栏、profile 与 Exact 切到该文件所在的单元，Exact 在单元根启动；同一语言的单元之间切换与跨语言切换一样冷启动。两个单元目录同名、配置与环境也相同时无法区分身份，这门语言回退为一个项目根单元：源码照常可见、可搜索、有大纲和关系，但 Rust `crate::`、Python 包路径等跨单元模块身份按项目根近似，rust-analyzer 显示现有的“缺少配置”原因。
- 不是 Git 仓库的目录（包括仓库的子目录，Git 不向上查找）按目录快照打开，没有提交历史，其余行为相同。
- 工具栏的版本选择器沿 HEAD 的第一父链列出提交，每页 500 条，列表到底后可“加载更早的提交”；搜索按 SHA 前缀、提交摘要、分支名和标签名匹配，不区分大小写。输入同时按仓库解析（完整或短 SHA、分支、标签、`HEAD`、`HEAD~N` 等 revision 表达式），能解析到 commit 就在列表顶部显示一条可选择的“解析结果”，解析不到则没有这条；解析出的提交本身已是过滤命中时不另加一行，而是把那一行提到最前。
- 命令行一次只分析一门语言：`resolve` 按位置所在文件的后缀推断，其他命令未给 `--language` 时取源码文件最多的语言，并在 stderr 写明。
- 一个项目对应一个窗口。再次打开同一实际路径（含符号链接或 `.`/`..` 别名）激活现有窗口，远端目录以同一 `主机:路径` 判断；新项目优先使用空白窗口。
- 每个窗口拥有自己的项目、索引、Exact 会话、检出目录、标签、导航历史和布局。信任与书签是应用共享资源。关一个窗口不应关闭其他项目。
- 文件树显示常规非符号链接文件。工作区默认跳过 `target`、`node_modules`、`.build`、`venv`、`.venv`、`__pycache__`、`dist`、`build`、`vendor`，`.git` 始终跳过（列表见 [ProjectPathRules.swift](../Sources/CodeInsightCore/ProjectPathRules.swift)）。工作区捕获不按 `.gitignore` 筛掉文件；commit 的 tracked 文件既不因 `.gitignore`，也不因默认跳过目录而消失。
- “文件 → 项目排除规则…”为当前项目编辑排除规则：每行一条 glob（语法同“搜索选项”的路径过滤），`!` 开头表示包含，后面的规则覆盖前面的，因此 `!build/` 可以恢复默认跳过的目录（连同其中嵌套的默认跳过目录）。与 `.gitignore` 相同，被排除目录里的文件不能单独重新包含。被排除的路径不进文件树、不建索引、不参与搜索和关系查询；工作区与 commit 快照都生效（commit 只应用用户规则）。规则只保存在本机应用数据里、按项目实际路径区分，不读取也不写入仓库中的任何规则文件。保存后走 Refresh Index，标签、阅读集、书签、轨迹和布局保留。
- 有规则排除时，文件栏标题右侧显示被排除的路径数（每个被剪掉的分支只计最上层一项），点击列出这些路径并可进入编辑；项目搜索底部同样写明“按项目规则排除 N 个路径”。仍打开着的被排除文件（或经 Exact 跳入的被排除文件）在路径栏显示“已排除 · 不参与索引”，可继续阅读。
- 工作区里读不出来的文件（如没有读权限）不会让打开失败：捕获时跳过，不进文件树、索引和搜索；文件栏标题右侧的同一个计数按钮写明“N 个文件无法读取”（与规则排除同时存在时两个数字都显示），点击列出这些路径。Refresh Index 重新捕获后计数随之更新。commit 中读不出 Git 对象仍是错误。
- 索引来源的导航要校验目标内容身份。文件已变化时提示刷新索引；刷新重新捕获工作区，同时保留标签、阅读集、书签、轨迹和布局。
- 阅读会话按项目保存。重新打开可恢复文件、位置、标签、前进/后退、轨迹与阅读集；旧 worktree 只能对当前工作区尽力重放，不声称恢复过去的实时文件。
- 清除阅读会话是显式操作。保存失败、较新格式、暂不可读或项目卷离线时不静默覆盖原会话。会话恢复未完成（包括被刷新或切换快照打断）时，在用户第一次开关、切换标签或跳转之前不写会话。

### 远端目录（ssh）

“文件 → 打开远端目录…”（默认 `⇧⌘O`）弹出一个输入框，填 `主机:/绝对路径`，回车打开。主机是 ssh 认得的名字，通常是 `~/.ssh/config` 里的 Host；不能以 `-` 开头、不能含空白。路径必须以 `/` 开头，`..` 被拒绝，`.`、重复的 `/` 和末尾的 `/` 被去掉，所以同一个目录只对应一个项目。认证、密钥、跳板机全部交给系统 `/usr/bin/ssh` 和用户自己的 ssh 配置，Cairn 不保存任何凭据。ssh 以 `BatchMode=yes` 运行：需要输入口令、确认主机指纹等交互的连接直接失败，错误里给出 ssh 最后一行原话和一条可以复制到终端运行的命令（`ssh -o BatchMode=yes -- 主机`），在终端里处理好之后再打开即可。远端需要 `bash`；有 `python3` 时用它，否则退到较慢的 bash 脚本。压缩用远端的 `zstd`，没有时用 `gzip`。

窗口标题、项目名、最近项目和欢迎页都显示 `主机:路径`。会话、索引缓存和排除规则按远端项目各自保存，书签也按项目区分，不与本机同名路径或另一台主机的同名路径混用。

可用：文件树、阅读与非源码预览、索引、项目搜索、大纲、项目符号、上下文（句法层）、AI 提问与文件导读（`history` 工具与非 Git 目录一样说明没有历史）。不可用：精确分析（状态栏显示“精确分析：不可用”，原因为“远端项目暂不支持”；“信任此仓库…”不可用）；版本选择器、blame、提交间比较等历史功能，表现与非 Git 目录相同。

捕获范围与本地工作区一致：同样跳过默认目录、应用项目排除规则，不按 `.gitignore` 筛掉文件，不含符号链接。索引、搜索、上下文和 AI 工具读的是捕获时的内容；远端文件在捕获后变化或被删除时，按本地相同的方式报告为已变化。

Cairn 不在本机保存远端文件的副本：源码只在内存里的源码字节缓存中，重启后第一次打开要重新取回。本机存的是一个只记录主机与路径的占位目录（`~/Library/Application Support/CodeInsight/remotes/` 下），以及与本地项目相同的索引缓存、会话和排除规则；阅读集的摘录与导读稿件也像本地项目一样存在应用数据里。从没成功打开过的目标（例如连不上的主机），在窗口关闭或改开别的项目时删掉它的占位目录；打开过的项目的占位目录不会自动删除。

连接断开后，下一次需要读远端的操作发现断开时，状态栏显示“已断开与 主机:路径 的连接”和“重连”按钮；点它或“刷新索引”（`⌘R`）会重新连接并重新捕获。阅读器每次打开文件都向远端读当前内容；断开期间读不到，改为显示捕获时取回、仍在内存里的那份源码或配置文件（可能已不是远端的现状，状态栏的断开提示一直在），图片等没有取回过的文件打不开。断开期间读不到的内容不显示成“没有结果”：搜索把读不到的文件计为截断，校验读不到的跳转目标不报告为“已变化”。刷新时，大小与修改时间都没变的文件不重新传输或重新哈希（源码还要仍在字节缓存里）；这依据的是同一窗口上一次捕获的记录，只在内存里，所以重启或重新打开后的第一次捕获仍会重新取回全部源码、在远端重新哈希其他文件。和 Git 的索引一样，这里信任大小加修改时间：内容被改成同样大小、修改时间又没变的文件会漏检，但读取时仍核对哈希，不会显示错的内容。

## Reader 与导航

单击文件打开可复用的预览标签；双击、Open in New Tab 或 Keep Open 将其保留。恢复的标签是保留状态。`⌘P` 快速打开，查询前缀 `>`、`@`、`#`、`:` 分别选择命令、文件符号、项目符号和行号。本文快捷键均指默认绑定。

Python 文件大纲收录模块作用域内以单个名称为目标的赋值，同名只列第一次。单击条目跳到源码中的变量名。

主阅读区只读，支持选区、复制、查找、折叠、换行、比较、语法样式及同名标识符高亮。复制始终来自原始源码，不从折叠占位符、连字字形或着色显示文本反向生成；Overview 骨架例外，复制得到的是骨架文本。

Full、Structure、Overview 和 Focus Scope 是文件 Reader 的阅读方式，不适用于非源码预览和阅读集。Full 显示整个文件，Structure 折叠函数体。

JavaScript（`.js`、`.jsx`、`.mjs`、`.cjs`）不是分析语言，但按源码阅读：按 TSX 语法着色、折叠，有大纲、作用域条、Focus Scope、文件内查找和三种阅读方式；比较时也按 TSX 计算差异和函数变更。它不进索引、没有 Exact，所以悬停卡片、跳转和关系没有结果（右键菜单里的关系命令仍可点，关系面板只显示空状态），也没有同名高亮和括号匹配；JavaScript 文件不提供书签（见“书签”）。超过约 20 万字节的 JavaScript 文件（通常是压缩后的单行包）仍显示为预览（见“非源码预览”），因为长行带着色会让阅读区卡住；它的面板布局按源码保留（大纲显示没有符号），分屏和比较里同样是预览。

Overview 对 Rust、Python、TypeScript（`.ts`、`.tsx`）和 JavaScript（`.js`、`.jsx`、`.mjs`、`.cjs`，按 TSX 语法提炼）文件显示骨架：按固定规则从源码提炼的简化代码，类型和函数都按它们在源码里的顺序出现。类型各占一行（Python 和 TypeScript 的 `class` 行在类的位置，方法跟在后面；TypeScript 的 interface、enum 和对象类型别名列出成员名）；主线上的函数（入口、调用了本文件函数的、不少于 10 行代码的，或 Jev 评为主线的）显示签名、关键语句和结尾，其余函数就地只列一行签名。多行的函数块前后各空一行，连续的单行之间不空行；源码里同一行上的几条语句合成一行，所以行号栏从上到下严格递增。TypeScript 和 JavaScript 的函数包括函数声明、值为箭头函数或函数表达式的顶层变量、类方法和值为箭头函数的类字段；骨架去掉类型注解、类型实参、`as`/`satisfies`/非空断言和 `async`/`await`（只剩 `await` 的括号一并去掉），签名保留默认值和返回类型；对象字面量和 JSX 整体算一行，超过 120 列在词边界截断加 `…`；`switch` 的每个 `case` 是一条语句。骨架为空的文件和 Go 的 Overview 仍是折叠，只留签名和顶层项。骨架与源码同字体、同主题、同样着色，没有折叠。行号栏显示每行对应的第一行源码行号，空行不显示，栏宽按最大的号码；点击行号切到 Full，像跳转一样把那一行完整显示出来（不被顶部的作用域条遮住）并显示落点标记。骨架上的右键菜单有“复制”（有选区时可用）和“在完整视图中查看此行”（等同点击该行行号，空行上不可用）两项，另有系统按选中文字附加的项。

进入 Overview 时，取 Full 里第一条没有被顶部作用域条盖住的源码行（顶边压在条下不到 3 点仍算可见），落在包含它的骨架行（有几行都包含时取起始最靠后的一行），没有骨架行包含它时取在它之后最近的一行，这一行放在视口顶部。离开 Overview 时，如果没有滚动过骨架（顶行仍是进入时落到的那一行），回到进入前源码阅读器的原位，连同行内的滚动偏移；进入前的顶行没有对应骨架行（注释、被省略的语句、只留签名的函数体）时也一样。滚动过骨架，则把骨架顶部一行对应的源码行放在 Full 里作用域条下方第一条可见的位置。进出 Focus Scope 同样算一次离开和回来。记下的原位只对同一文件的同一内容有效，换文件、内容变化或跳转到别处后作废；点行号、右键“在完整视图中查看此行”、`⌘F` 和打开搜索结果离开时，仍按各自的目标落点。会话记录的阅读位置仍是视口最顶的源码行。骨架可以选择和复制。

骨架显示时，Ask AI、书签、悬停与跳转、关系、同名高亮、括号和折叠命令不可用，因为光标在骨架上，不在源码上。文件内查找（`⌘F`、查找下一个/上一个）在源码上进行：先切到 Full 并停在同一源码行，再打开查找条。阅读位置、标签、阅读轨迹、会话记录和大纲跟随都按骨架顶部一行对应的源码位置记录。从别处跳到这个文件时落在对应的骨架行，落点标记只出现在骨架上；打开搜索结果或差异行会先切到 Full。在骨架上进入 Focus Scope，聚焦光标所在骨架行对应的源码作用域；退出后回到骨架。不超过 10,000 行的文件在进入 Overview 或切换文件时当场提炼，骨架立即出现；更大的文件在后台提炼，期间阅读区显示“正在提炼概览…”，骨架到达后替换。在同一文件上来回切换阅读方式时复用，不重新提炼。最近用过的 8 份骨架按内容缓存，在这几个文件之间切换不重新提炼。命令行 `codeinsight overview <文件>` 输出同一份规则骨架，每行前面是对应的第一行源码行号。

“设置 → AI”里保存 Jev 密钥后，Rust、Python、TypeScript 和 JavaScript 文件的 Overview 借助 TypeSafe 的 Jev 服务改进骨架。Jev 只判断哪些函数在主线上、哪些被规则省略的语句要保留，改写规则不变；入口函数始终在主线上，没有得到评分的函数和语句照规则处理。每个文件一次请求，发往 `https://api.typesafe.ai/v1/systemone`（模型 `jev-latest`）：内容是该文件的全部代码，去掉空行、注释（含行尾注释）和 Python 文档字符串，每行前面是原行号；另附每个候选函数（从入口按调用顺序到达、本身不是入口、提炼后有内容的函数）和每条被规则省略的语句（Python 文档字符串除外）各一个问题，问题里引用语句第一行的代码（同样去掉注释）。请求超过 150,000 字节的文件不发送，只用规则版本。同时满足以下条件才发送：已保存密钥；文件在当前项目目录内（解析符号链接后）；没有被项目的排除规则或默认跳过的目录排除；主阅读区正在 Overview 显示这个文件的骨架。分屏和比较面板、命令行 `codeinsight overview` 只用规则，Go 不受影响。评分按文件内容、语言、规则版本和模型名缓存在本机（应用支持目录下 `Cairn/<包标识>/overview-scores`），只存评分，不存代码或骨架。有缓存时直接显示评分版，不先显示规则版，也不发送；没有缓存时先显示规则版并发送，期间骨架区右上角浮着转圈和“正在完善概览…”，不挪动内容；成功后写入缓存，原地换成评分版，顶部的源码行不变。失败时提示消失、保留规则版，状态栏短暂说明一次原因（密钥未被接受、无法连接、服务繁忙或结果不可用）；本次运行中同一内容不再发送，直到密钥改变。离开 Overview、切换文件或内容改变时取消进行中的请求，晚到的结果不会替换任何骨架。服务繁忙（429、529）和连接失败各最多重试三次，间隔 1、2、4 秒；单次请求 30 秒超时。没有密钥时 Overview 只用本地规则，不联网，已缓存的评分也不使用。密钥是钥匙串里单独的一项（服务名“Cairn Jev scoring”；包标识不是 `dev.cairn.Cairn` 的构建用“Cairn Jev scoring (<包标识>)”），与 AI 提问的密钥分开；设置页上始终显示发送什么、发到哪里、本机存什么，不另弹同意框。

### 面板布局

窗口有三个面板区：左侧、右侧，以及阅读区下方、两侧之间的底部区。文件、大纲、项目符号、关系、上下文、搜索结果、文档是面板；阅读区（含分屏和比较）、阅读轨迹条和状态栏不是面板，不移动。同一侧的面板上下堆叠，分隔条可调高度；底部区的面板左右并排，分隔条可调宽度；一个区没有可见面板时收起，阅读区占满。没有标签页或浮动面板窗口。

每个面板的标题栏有标题、`⋯` 和 `×`。`⋯` 菜单提供移到左侧、移到右侧、移到底部、上移、下移（底部区为左移、右移）和关闭，当前位置做不到的项置灰。拖标题栏可放到任一区的任意位置：拖动影像只有标题栏，目标区显示强调色指示线，鼠标在某面板前半部（侧区的上半、底部区的左半）表示放到它前面、后半部表示放到它后面，空白处表示放到末尾；拖动期间空着的区显示 72pt 宽（底部区为高）的“放到这里”，松手后仍为空则收起。

“视图 → 面板”列出全部面板，勾选表示正在显示。关系（`⌃⌘R`）和“显示/隐藏搜索结果”沿用原命令并移入这个子菜单；项目符号默认 `⌃⌘S`（显示面板并聚焦过滤框，面板已显示且过滤框有焦点时再按一次隐藏）；文件、大纲、上下文、文档的开关默认无快捷键，可在快捷键设置里绑定。上下文默认跟随自动规则：光标处有可显示内容时出现，没有时收起。面板的 `×`、取消勾选或状态栏 Context 按钮关闭它后不再自动出现，直到再次打开或切换预设；重新打开时即使暂无内容也立即显示，有内容后回到自动规则。

预设 `⌘1`–`⌘4` 只切换显示组合，不改变放置和宽度：阅读 = 文件、大纲；关系 = 文件、大纲、关系；比较 = 文件并打开比较分屏；专注 = 全部隐藏，上下文也不再自动出现。前三种的上下文跟随自动规则；项目符号、搜索结果和文档在四种预设下都隐藏。切换预设后仍可单独开关面板。关闭比较只关闭分屏，不改变面板显示。“视图 → 恢复默认布局”恢复放置、宽度、高度和显示：左侧文件、大纲、项目符号（240pt，项目符号默认隐藏），右侧关系、上下文、搜索结果、文档（300pt），底部为空（260pt 高），只显示文件、大纲和自动上下文。

布局是应用全局一份，保存每个面板的位置和显示、两侧宽度、底部高度、面板在所在区内的相对尺寸及分屏比例，不按项目或预设区分；各项目窗口读写同一份，已打开的其他窗口不实时同步。只在实际改动布局时保存：分隔条拖动结束、移动或开关面板、切换预设、恢复默认布局；会话保存、切到其他应用和关闭窗口不写布局，因此多个窗口时以最后一次改动为准，不会被另一个窗口里较旧的副本覆盖。启动和恢复阅读会话都不改变面板的显示与放置，单独开关的面板在重启后保持；会话只记住最后选择的预设（比较预设仍会重新打开比较分屏）。旧版本按预设保存的布局不再读取，升级后首次使用默认布局；保存的布局里缺少的面板（如新加入的项目符号）按默认位置和默认显示状态补回。

下列情况在全局布局之上临时隐藏面板，期间拖动分隔条不记录尺寸，离开后恢复：没有项目时隐藏全部；非源码预览只保留文件和项目符号；阅读集隐藏全部（在阅读集中查看证据会临时显示关系）；比较或参考分屏放不下时隐藏两侧，关闭分屏后恢复。

阅读区至少 320pt 宽、200pt 高。每侧的最小宽度取其可见面板的最大值（关系、搜索结果、文档 300pt，其余 180pt），底部区的最小高度取其可见面板的最大值（上下文 120pt、搜索结果和文档 240pt，其余 80pt），但这些是软约束：窗口放不下时两侧面板区按各自宽度的比例压缩，不会为了排版放大窗口；重新排布（如阅读集之后回到源码）落在同一压缩结果上，不会先压左侧。侧区内面板的最小高度和底部区内面板的最小宽度用同一组数值。上下文面板的头部分两行（控制、显示内容），在 300pt 的侧区中控制行会被压缩。

#### 项目符号面板

“项目符号”不需要输入名字就列出当前快照中全部已索引的声明，覆盖每个分析单元和语言；同一文件只出现在它所属的单元里，内容相同的两个文件各列一次。顶部分段控件切换两种组织方式，共用同一份数据与过滤：

- **按种类**：函数、方法、宏、结构体/类、枚举、枚举变体、Trait/接口、类型别名、impl、模块、常量/变量十一组，组标题带计数，默认折叠，只有一组时自动展开。组内按路径和位置排序，有过滤文字时按匹配评分排序。方法和枚举变体在组里平铺并在名称前显示所属（`Log::append`、`Shape::Circle`）。宏是 Rust `macro_rules!`；常量/变量包括 Rust `const`/`static` 和 Python 模块级变量（同一文件同名只列第一次赋值，元组解包、类体和函数里的赋值不算）。结构体/类/枚举行展开后列出自身字段或变体、同文件的同名 impl 及其方法；只有当这个名字在本单元只声明一次时，才把其他文件的同名 impl 也挂上，并标“按名称合并”——这是名称匹配，不是语义归属。字段不单独成组。
- **按模块**：多个单元时第一层为“语言 · 单元根”。Rust 每个 crate 根（`main.rs`、`lib.rs`、`src/bin/*.rs`）是一个节点，`mod` 声明与内联 `mod { }` 展开为子模块，任何根都到不了的文件（`examples/`、`tests/`、未被引用的文件）归入“未挂载的文件”；Python 按单元根下的目录（去掉 `src/`，`__init__.py` 代表包本身）；TypeScript 按目录加文件。Rust 方法挂在所在 impl 块下（`impl Log`、`impl Engine for BitCask`）。

每行有可见性记号（实心圆公开、半圆受限、空心圆私有，不适用不画）、种类图标、名称（匹配处加粗），右侧灰色 `路径:行号`，面板窄于约 200pt（接近 180pt 最小宽度）时省略所属和路径，拖宽后立即恢复；多语言项目在名称前标 `rs`/`py`/`ts`。过滤框与 `⌘P` 的 `#` 用同一套匹配，停顿约 150ms 后执行，不设 2,000 条上限；有文字时不匹配的叶子隐藏，有匹配子项的容器保留、自动展开，自身不匹配时灰显。过滤按钮可勾选十一组加“字段”、开关“仅公开”和选择范围（整个项目 / 焦点文件所在目录，含子目录）。“仅公开”只看声明处的修饰：Rust `pub`（`macro_rules!` 带 `#[macro_export]` 才算公开）、TypeScript 顶层 `export`（含后置 `export { x }`、`export default`）与类成员无修饰或 `public`、Python 不以 `_` 开头或 `__x__` 形式；受限（`pub(crate)`、`protected`）与私有一样被隐藏，trait 方法、枚举变体这类不适用的叶子保留，impl 块只在有通过的子项时灰显保留。组织方式、种类勾选、仅公开、范围是应用级偏好，过滤文字、展开与选中不保存。底部写“显示 N / 总数 个符号 · 文件数 · 语言”，无过滤时省略“显示 N /”。

单击或方向键选中一行即在预览标签中打开并闪烁声明名，焦点留在列表，Context 跟随（与搜索结果相同）；回车或双击把焦点交给阅读区。过滤框里 `↓` 进入列表；`Esc` 先清空过滤文字，再次 `Esc` 把焦点还给阅读区。右键菜单：打开、在右侧打开、查看调用者/被调用者（仅函数）、引用、实现、高亮此名称、在文件树中显示、复制限定名。工具栏的准星按钮（“视图 → 定位当前符号”，默认无快捷键）取 Context 当前符号，没有时取光标处的声明，在当前组织方式下展开并选中；被过滤隐藏时只提示，不改过滤。面板不自动跟随光标。

索引中显示“正在索引…”；首帧缓存会话到完整会话静默替换，展开与选中不丢。快照变化（切换 commit、刷新、保存排除规则）后旧列表标为过期且不能跳转，新数据到达后按路径、内容身份和名称范围恢复选中，找不到则清选。`?` 按钮说明不列出的条目（见“当前限制”）。

### 分屏阅读

文件树和标签页的右键菜单有“在右侧打开”；“视图 → 在右侧打开当前文件”（默认 `⌘\`）把当前文件的当前位置放到右侧。右侧是单文档参考栏：顶部显示路径和关闭按钮，没有标签栏，在右侧再打开别的文件直接替换。“视图 → 关闭分屏”或顶部关闭按钮收起右侧。

最后点击或移动光标的一侧是焦点一侧，顶部有一条 2pt 强调色边；它决定 Context、Outline 和高亮条计数显示哪一侧的文件，Outline 点击也跳到这一侧。在右侧 `⌘` 单击、跳到类型定义，或右侧聚焦时双击 Context 正文，都在右侧打开目标。前进/后退作用于焦点一侧，两侧各自记录历史；阅读轨迹仍是一条，不区分左右。

分屏与比较互斥：进入比较或 Focus 预设时右侧让给比较或收起，退出后恢复原来的参考栏；左侧显示非源码预览时右侧也暂时收起。分屏的文件和位置随阅读会话保存和恢复，项目外的路径不会被恢复。打开时两侧各需至少 320pt，放不下时暂时隐藏两侧面板区（关闭分屏后恢复），仍放不下则提示窗口太窄。右侧可以折叠、显示多色高亮、括号配对和块尾注解，并显示书签标记；文件内查找、作用域标题和书签切换仍只在左侧可用，关系面板结果和 Context 的右键菜单没有“在右侧打开”。

### 光标、接收者与上下文窗口

解析的是光标下的 token：`ps.get()` 的 `ps` 是接收者绑定，`get` 才是方法；`self.repo.open()` 的 `repo` 是字段/类属性，`open` 是方法。方法分派仍可使用接收者类型。这条规则同时适用于单击、定义导航和悬浮文档。

上下文窗口区分“指向的符号”与“当前显示的内容”：

- 指向值绑定时，优先显示可解析的类型，头部如 `ps: &S → S`；点击两端可切换声明与类型。
- `⌘` 单击、查看引用/调用关系、悬浮文档针对原符号；双击 Context 正文打开当前显示目标。
- 本地索引没有声明、首个本地候选停在导入/use 绑定（点在导入行，或点在同文件里对导入名的使用，如 `new Tokenizer()`、`let t: Tokenizer`、`helper()`；TypeScript 的导入名同样算），或索引根本不认点击处的标识符（如类型里的 `TcpListener`、`torch.cuda` 的 `torch`）时，`⌘` 单击等语言服务器的定义并打开它，目标可以是依赖文件（只读依赖标签）；精确层未就绪或没有答案时不等待/不动，保持原行为（跳到本地候选或不动）。本地有真正的声明时直接跳，不等精确层。普通单击索引不认的标识符时仍保留上一项内容，Context 不显示精确结果。
- “跳到类型定义”（默认 `⌃⌘J`、`⇧⌘` 单击）打开类型目标，在阅读轨迹中记为类型导航。无目标时说明原因，不随意跳到同名符号。
- 句法类型先回答，Exact `typeDefinition` 可随后增强。用户已手动切换显示端时，晚到结果不能抢回显示。等待结束、取消或空结果必须退出“解析中”；精确层明确答复没有类型时显示“未找到类型”，未就绪或没有答复时仍显示“类型需要精确分析 · 未就绪”。语言服务器不提供 `typeDefinition`（TypeScript、Pyright）时，句法拼不出类型的绑定不停在“类型需要精确分析 · 未就绪”，而是回到声明候选并接收 Exact 定义：导入名会显示语言服务器给出的目标（可以是依赖文件），与 `⌘` 单击打开的一致。
- 语法层识别明确注解、部分包装类型、`self`/`this` 与有限的构造表达式，不是完整类型推断。原始类型留在声明；可识别的类型别名留在别名；泛型只有明确单约束时才尝试约束目标。两跳的确定性不高于其中较弱的一跳。

“符号”和“所在函数”是独立于图钉的两个跟踪模式。符号模式跟随单击与键盘光标；键盘句法查询防抖约 150ms，Exact 等同一符号停留约 400ms，单击立即请求。空白或非符号位置保留已有内容并标明保留状态，不取消已发出的当前查询。

所在函数模式选择最内层函数/方法，函数外退到所属类型；显示签名、文档和主体摘要，仅用句法信息，不发 Exact 请求。在项目内的文件里，它和面包屑一样跟随焦点一侧光标的每次变化：单击（含带修饰键的单击）、键盘移动，以及跳转定义/类型、大纲、前进/后退和会话恢复带来的位置变化；符号模式只跟随用户自己的单击与键盘移动。双击正文打开该声明并落在名称上，面板保持不变。依赖文件（只读依赖标签）里的位置不更新面板。两种模式均可固定；固定后不随光标变化。跟踪模式随项目会话恢复，图钉状态不恢复。

### 悬浮文档

Rust、Python、TypeScript/TSX、Go 支持延迟悬浮文档；也可用 `⌥` 单击或“显示符号文档”。优先使用语言服务器结果，不可用时用源码签名与 doc comment/docstring/JSDoc/Go 文档注释，并说明降级原因。无注释与缺少本地依赖源码是不同状态。语言服务器有正文时不附 Safe 模式等限制说明（它们解释的是缺失）；commit 分析借用了工作区依赖时，有正文也附“依赖来自当前工作区，可能与该 commit 不一致”。

卡片可容纳签名、Markdown 和滚动正文；移进卡片可继续阅读，Esc 关闭。指针在卡片上时，被卡片盖住的代码不触发悬浮，卡片不会换成下面那个符号的。指向链接时卡片保持已滚动到的位置。卡片中的符号链接尝试在应用内导航；这不等于普通 HTML/Markdown 文件预览会开放外部网络。

装有 Dash（`dash-plugin://` 有处理程序）时，卡片末尾和阅读区右键菜单各有一条"在 Dash 中查看"，用 `dash-plugin://query=…` 把符号交给 Dash 搜索，不限定 docset，第三方库的 docset 也会命中。查询词：Rust 中 rust-analyzer 的精确结果带有定义路径（如 `std::sync::poison::mutex::Mutex`），只取路径最后一段加标识符，发送 `Mutex::lock`（完整定义路径常常不是文档所在的路径，std 把它重新导出为 `std::sync::Mutex`）；路径最后一段就是该标识符时只发标识符。Python、TypeScript、JavaScript 中标识符前紧挨着 `.` 和另一个标识符时，带上这一层接收者，如 `os.getenv`、`threading.Lock`（只取一层，`self`、`this` 不算）。其余情况发送标识符本身，由 Dash 的搜索结果列表消歧。未安装 Dash 时这两处入口不出现；Dash 未运行时由系统启动它。

#### 文档面板

装有 Dash 时，“文档”面板在应用内显示 Dash 的文档页；Dash 没有可直接显示的条目时，显示该符号的悬浮文档。三个入口都作用于标识符，不分语言，没有语言服务器的文件也可用：阅读区右键菜单“在文档面板中显示”（在“在 Dash 中查看”旁，光标下没有标识符时置灰）、悬浮卡片里“在 Dash 中查看”旁的同名链接、“关系 → 在文档面板中显示”（默认 `⌃⇧D`，作用于光标处；`⌃⌘D` 是系统“查询”，在阅读区里到不了菜单）。未安装 Dash 时三者都不出现。面板不跟随光标，只在这些显式动作时查询。

查询词与“在 Dash 中查看”相同；右键和 `⌃⇧D` 在卡片正显示该符号时复用卡片的精确结果。Cairn 通过 Dash 的本机 API 在全部 docset 中搜索，按当前文件的语言排序：该语言的 docset 在前（Python：`python`；Rust：`rust`、`crate`；TypeScript/JavaScript：`typescript`、`javascript`、`nodejs`，按 Dash 的 platform 区分），其次是用户贡献的 docset（第三方库，Dash 不记录语言），最后是其他；组内保持 Dash 的顺序。一个结果是精确命中，当且仅当它的名字等于查询词按 `::` 或 `.` 拆开的最后一段，其余各段都作为完整的词（区分大小写）出现在页面地址里（所以 `io` 不命中 `asyncio`，`Mutex` 不命中 `mutex/lock.html`）。只有一个结果或只有一个精确命中时直接加载；限定名（如 `Mutex::lock`）有多个精确命中时，在排在最前的那个所属的 docset 里取页面路径最短的一个（std 的 `std/sync/struct.Mutex.html` 先于 `std/sync/poison/struct.Mutex.html`）；裸标识符有多个精确命中、其中恰好一个属于当前语言的 docset 时加载它（Python 文件里的 `getenv`）；其余多个精确命中（如 `acquire`）或没有精确命中时不自动加载，等用户在头部的结果下拉里选择。结果多于一个时下拉列出全部结果（名称 · 类型 · docset），切换即加载。新查询取代进行中的查询。

悬浮文档回退：动作发出时悬浮卡片正显示该符号（卡片里的链接总是如此；右键和 `⌃⇧D` 只在卡片恰好显示光标处符号时），面板记下卡片的签名与正文。Dash 不可用、搜索无结果、有多个结果待选，或唯一的结果不是精确命中（如 Python 的 `FilesystemPermission` 只搜到 C++ 的 `permissions`）时，面板显示这份悬浮文档，头部第二行写“悬浮文档”和 Dash 没有页面的原因；Dash 的结果仍可在下拉里选择，选中后显示 Dash 页面。没有悬浮文档时行为不变：唯一结果直接加载，其余情况显示说明文字。入口仍只在装有 Dash 时出现。

头部显示当前条目（名称 · 类型）、来源（Dash · docset）、“↗ 在 Dash 中打开”和后退按钮。页面在受限的网页视图中按自带样式显示：页面脚本关闭，不保存网站数据，只允许连接 127.0.0.1，Sphinx 和 rustdoc 的导航栏被隐藏，直接定位到条目的锚点。指向 Dash 本机服务器的链接在面板内打开，可以后退；其他网页链接交给默认浏览器，面板不变。在面板内跳到别的页面后，副标题改为网页标题。深色主题下页面使用 Dash 自己的反色样式，滚动条另配深色，尚未绘制的区域露出面板的深色背景而不是白色；切换主题时重新加载当前页。

第一次在文档面板中显示时，面板自动出现在它在布局中的位置（默认右侧最下），占该侧 40% 高度并保存；之后显示状态随布局保存，`×` 关闭后不会自动出现，下一次显式动作再打开。面板内容不跨重启保存，重启后显示提示文字。Dash 未运行、API 服务未开启（Dash → Settings → Integration）、搜索无结果或试用期已过时，面板显示悬浮文档（有的话）或说明文字；页面加载失败时显示说明文字。面板不启动 Dash，也不改 Dash 的设置。

### AI 提问

“AI”面板（视图 → 面板 → AI，默认在右侧最下、隐藏）就当前项目的代码回答问题。模型由用户在“设置 → AI”配置一份：协议（OpenAI 兼容的 Chat Completions，或 Anthropic Messages）、Base URL（OpenAI 兼容写到版本，如 `https://api.openai.com/v1`；DeepSeek 可写 `https://api.deepseek.com`；Anthropic 写主机，如 `https://api.anthropic.com`；留空即用所选协议的官方地址）、模型名和 API 密钥。地址和密钥齐备后（本机地址不需要密钥），设置页向该地址请求模型列表（OpenAI 兼容与 Anthropic 都是 `GET …/models`，只带密钥、不含代码），获取期间模型名旁显示进度和“正在获取”提示，完成后旁边的“选择…”列出结果；也可以手填列表里没有的名字，获取失败时以警告样式显示服务返回的原因。密钥存放在登录钥匙串（服务名“Cairn AI provider”；包标识不是 `dev.cairn.Cairn` 的构建，如测试包，用各自的“Cairn AI provider (<包标识>)”，不会去读正式版的密钥），每次启动只读一次，其余存在用户默认设置。“测试连接”让模型调用一次工具：服务不支持工具调用就无法回答代码问题，没有不读代码的降级模式。

协议也可以选“ChatGPT 套餐”（Sign in with ChatGPT）：不填地址和密钥，改为点“使用 ChatGPT 继续”，在系统浏览器里登录并允许 Cairn 使用套餐；浏览器回到 `127.0.0.1` 上临时监听的端口（只接受带本次 state 的 `/auth/callback`），Cairn 用 PKCE 换得令牌。首次登录时 OpenAI 为这台机器上的 Cairn 发一个客户端 ID，之后重新登录沿用它。令牌（访问令牌约 1 小时，刷新令牌每次刷新都换新）存在钥匙串（服务名“Cairn ChatGPT sign-in”），客户端 ID 和账号邮箱存在用户默认设置；访问令牌剩不到 5 分钟时，下一次提问或导读前先刷新，并发的请求共用一次刷新，刷新令牌被拒才清掉登录。请求一律走 `https://api.openai.com/v1` 的 Responses API（`store:false`、流式），模型列表来自同一地址的 `GET /models`（只列 `visibility` 为 `list` 的，按服务端顺序，未选模型或所选模型不在列表里时取第一个）。登录后设置页显示“已连接：邮箱”、“管理用量”（`chatgpt.com/settings/usage`）和“断开连接”（清掉本机令牌并请求撤销）；首次登录成功后弹出一次“正在使用你的 ChatGPT 套餐”说明（用量计入套餐、可在 ChatGPT 设置中查看用量、设上限或断开），“知道了”关闭；AI 面板顶部在模型名后写“使用 ChatGPT 套餐”，旁边是“管理用量”链接，达到套餐限额、登录失效或未允许使用套餐时给出对应说明。实现按公开协议独立编写，没有使用 DevKit（非商用许可）的代码或品牌素材；登录时 ID token 用 OpenAI 公布的签名公钥（`auth.openai.com/.well-known/jwks.json`，按 `kid` 取，只接受 RS256）验签，再核对签发方、受众、nonce 和有效期；公钥取不到则登录失败、可重试。刷新返回的新 ID token 不再核对（它只用来显示邮箱）（令牌经 TLS 直接取自令牌端点，只用来显示邮箱）。授权请求不带 `ext_agent_host_id`：2026-11-22 带上它时 auth.openai.com 直接返回 `invalid_authorize_request`。

已验证与限制：2026-11-22 用真实 ChatGPT 账号验证。先用一次性脚本驱动辅助程序：Responses API 的流式工具调用、回传工具结果、同一对话追问都通过；genai 在 api.openai.com 上默认附带的 `prompt_cache_options` 被套餐通道拒绝（400），改为发送 `prompt_cache_key` 后通过；刷新令牌每次都换新，访问令牌 `expires_in` 为 3600。随后在打包的测试包（隔离包标识，LCU 后台驱动）中完成：登录后显示“已连接”、“管理用量”和“断开连接”，模型列表取回且自动选中第一个（`gpt-6.2-sol`）；“测试连接”显示可以调用工具；在 AI 面板就一个 Rust 文件提问，授权提示写明 api.openai.com，回答经一次查找、两次读取，用时 18.2 s，行号引用正确，面板顶部显示“使用 ChatGPT 套餐”；“断开连接”后钥匙串项和邮箱被清掉，客户端 ID 保留。同日另用一个每次请求前都刷新令牌的临时测试包：断开后沿用已保存的客户端 ID、换端口重新登录成功；连续两次“测试连接”和重启后再测都通过（每次都换用上次保存的新刷新令牌）；用套餐为 main.rs 生成了一份通过锚点核对的导读。登录等待期间回环端口只绑定 127.0.0.1，state 错误、路径不对或 Host 不符的请求都得到 404，登录继续等待。加入 ID token 验签、欢迎说明和面板“管理用量”链接后，同日再用真实账号登录：登录成功（即通过了对 OpenAI 实时公钥的 RS256 验签），首次登录弹出欢迎说明（用户确认看到并点了“知道了”），AI 面板顶部显示“管理用量”。验签本身另有回归测试（本机生成的 RSA 密钥：篡改载荷、换用另一把已公布的钥匙、未知 `kid`、`alg:none`、缺签名都被拒）。重新打包的测试包签名变化后，读取钥匙串里的令牌会弹出系统授权框，未允许前模型列表停在“正在获取”、“断开连接”无反应（用 API 密钥时同样如此）。未验证：点击面板上的“管理用量”打开网页、令牌自然过期（1 小时）后的刷新时机、达到套餐限额时的提示、Business 工作区。后台切换窗口后，面板的空状态提示仍停留在登录前的文字，直到窗口重新成为主窗口才更新；正常关闭设置窗口回到项目窗口时会刷新，这一点未单独实测。

一个窗口一段对话，不保存。对话绑定在第一个问题时显示的快照上（工作区或某个 commit），面板顶部写出快照与模型；追问沿用同一快照，“新对话”或切换项目会清空它，下一个问题改用当时的快照。切到别的 commit 后，卡片和引用仍按对话的快照打开文件，但不带行位置。

模型只能通过四个只读工具看代码，全部作用于对话的快照。工具按模型要问的问题划分，而不是按背后的数据来源划分；每次调用尽量一步答完，先给总数，结果按文件分组，截断时写明还剩多少，结果为空时说明是“确实没有”还是“没查成”及原因，末尾给一行下一步可用的调用。

- `read`：按行读文件，默认从起始行读 100 行，最多 200 行，带行号；头部写总行数和第一行所在的符号（如 `impl Parser › fn parse (lines 110–260)`），尾部写上下还有多少行。给目录时（项目根为空串）列出子目录和各自的文件数、文件和各自的行数。
- `search`：在已分析语言的源码文件里查文本或正则；查询里有大写字母才区分大小写，可按目录或 glob 限定范围。最多 50 条时按文件分组，每条带行号和所在符号；超过 50 条只给每个文件的命中数，并提示缩小范围。
- `symbol`：按名字查一个符号的定义、签名和一种关系：调用方（默认）、被调用、引用或实现。同名定义有多个时列出候选，让模型带上路径和行号再问；路径和行号也可以指向一次使用，用来查那次使用指的是什么。精确分析覆盖该文件、且仍停在对话的快照上时，由语言服务器回答（标 `[exact]`，签名取悬停信息）；否则由 Cairn 的索引回答（标 `[index]`），并写明没用精确分析的原因：还在准备、阅读区已切到别的快照、文件不在精确分析当前覆盖的分析单元里，或超时（每次请求 15 秒）。AI 不会为提问切换精确分析的单元；它跟随阅读区当前打开的文件。引用只由精确分析给出；索引只认得 Rust 的 trait 实现。落在项目外的位置（依赖库）只报告缩短后的路径（从包目录起，或以 `~` 开头），不可读取。
- `history`：只用于 Git 项目。对文件的一段行（默认整个文件）做 blame，按最后改动它们的提交分组、从新到旧列出，每个提交给出短 SHA、日期、行数和完整提交说明，最新的三个附上该提交对这些行所在位置的 diff（相对第一父提交）。未提交的行单独计数。不发送作者名，并去掉提交说明里带邮箱的尾注（如 `Signed-off-by`）。文件在该提交里新增时注明“新增”；提交里该文件路径不同（之后改过名）时不给 diff。blame 超过 20 秒即放弃。这个工具会发出快照里已不存在的旧代码，所以“只读快照”在这里的实际范围是“快照及其文件的历史”。

系统提示里附一段项目概览：快照、文件数、有没有 Git 历史、各语言的分析单元、精确分析的状态与覆盖范围、顶层目录和文件数。工具只能读快照文件列表里的文件，工作区中经符号链接指向项目外的路径会被拒绝；参数写错或缺少必填参数时明确报错并列出正确的参数；没有写入、执行或联网的工具。一个问题最多 15 轮工具调用；某一轮发出的输入（含历史）超过 8 万 token 时也一样：要求模型用已读内容作答，仍继续调用工具则停止并说明。下一个问题发出前，若上一轮输入超过 6 万 token，较早的工具结果换成一句说明（模型可用同样的调用重新取回），Anthropic 协议还会去掉较早的思考内容；服务商以超出上下文为由拒绝一个问题的首轮时，这样清理后重发一次。

每个问题下面依次是：一行阅读进度和流式显示的回答。阅读进行时这一行带转圈，每一步开始时就显示第几步、正在做什么（如“第 3 步 · 读取 src/lib.rs”“第 4 步 · parse 的调用方”）；结束后变成摘要（如“查找 3 次 · 读取 6 次 · 34.5 s”），回答紧接其下。这一行默认折叠，点击展开为逐步列表，每步一行：指向代码的一步写出位置（读取的行、查到的定义、查过历史的行，如 `src/lib.rs:1–9`），指针停留时显示开头几行、签名或最新提交的摘要，点击在阅读区打开；其他步骤写出做了什么、得到几条。回答流式显示时，只要停在底部就跟随到底；向上滚动后不再被拉回。回答里形如 `path:line`、`path:start-end` 且能对应到快照文件的引用（也接受只写文件名、且只有一个文件匹配的写法）可点击跳转；其他网页链接交给默认浏览器。回答按 Markdown 显示，但不加载任何图片（远程、本地或 data URI 都只显示替代文字），也不加载其他资源。发送键在回答时变为停止；停止后可以继续追问。

针对一段代码提问：在阅读区选中至少 3 个字符后，选区首行的行号位置换成一个提问图标；点它、右键菜单“询问 AI”或“关系 → 询问 AI”（默认 `⌘I`；解析检查器为 `⌥⌘I`）都会在选区旁弹出小输入框，带“解释”“谁在调用它”“为什么这样写”三个按钮，回车发送、`⇧↩` 换行、`Esc` 收起，空问题按“解释”处理。没有选区（或选区不足 3 个字符，例如右键时选中的单字母标识符）时，这些入口改用光标所在的最内层符号（函数、类型等）的完整范围，光标不在任何符号里则提示音。发送后显示 AI 面板，并开始一段新对话：问题前附上选中的代码（文件、行号与原文，最多 400 行），问题上方显示可点击的 `path:起–止`。隐藏行号时没有图标，菜单和快捷键照常可用。

隐私：某个项目第一次提问前，面板询问是否允许把该项目的代码片段、提交说明和历史改动发送到配置的主机；允许按“项目 + 主机”记住（2026-11-19 发送范围扩大到 Git 历史后，之前允许过的项目会重新询问一次），“设置 → AI → 忘记已允许的项目”清除全部记录。Base URL 指向本机（localhost、127.0.0.1、::1、`*.localhost`）时不询问，也不要求密钥。

实现：请求由随应用分发的辅助程序 `Contents/Helpers/cairn-ai`（Rust，[genai](https://github.com/jeremychone/rust-genai) 0.7.5）发出，它只连接配置的 Base URL；对话历史（含各家的推理内容与签名）保存在这个进程的内存里，工具由 Cairn 执行。辅助程序退出时进行中的问题失败，下一个问题重新启动它，之前的上下文不再带给模型。

已验证与限制：2026-11-18 用真实 DeepSeek（`deepseek-flash`、`deepseek-v4-pro`，思考模式开启）经辅助程序测试，两种协议的流式多轮工具调用和并行工具调用都通过，Anthropic 协议用 `https://api.deepseek.com/anthropic`；OpenAI、Anthropic 官方服务未测。Anthropic 的提示缓存未启用。输入阈值固定，压在 Claude Haiku 5.5 的 10 万 token 计价档以下，不按各模型的上下文窗口；一个问题中途超出窗口不重试，直接报错。阈值看的是上一轮的输入，一轮里的工具调用数不设上限，所以单轮仍可能超过 10 万 token。判断“超出上下文”靠匹配错误文字，各服务商的真实措辞未核对；不报告用量的服务商不会触发预算和清理。清理与提前作答在面板上没有提示。裁剪时去掉思考内容的依据：2026-11-21 用 `claude-haiku-5-5`（开启历史检查）实测，改动较早的工具结果而保留思考内容会被拒（400），去掉后通过；当时历史里只有一个思考块。长对话裁剪后的回答质量未用真实模型验证。2026-11-19 四个工具（`read`、`search`、`symbol`、`history`）在打包的测试包（隔离包标识，后台自动化）里接本机脚本化模型原生验证，项目为 ripgrep 克隆（三个提交、一处未提交改动）：工作区里同名的三个定义列为候选；`symbol` 的调用方、引用由 rust-analyzer 给出（标 `[exact]` 并写明“本机缺少依赖”等限制），只按方法名匹配到多个定义时列出候选而不替用户挑一个；`history` 按提交分组、新的在前，正文去掉带邮箱的尾注、不含作者名，只附改到所问行的 diff 块，未提交行单独计数，首个提交标“文件在此提交新增”；在提交上提问时历史只到该提交；对话中途阅读区切到别的提交后，`symbol` 改用索引回答并写明精确分析已切走；未知参数报错并给出用法，命中超过 50 处只给每文件计数，读取窗口默认 100 行、上限 200 行并给出续读调用；非 Git 目录里 `history` 说明没有历史、`symbol` 用索引作答。未验证：冷启动时精确分析未就绪立即退回索引（这次切换后 0.4 s 内已就绪，没出现）、慢工具时进度行的表现、已同意项目的重新询问（本机地址不询问）、与改造前工具的真实模型对比。

### 文件导读

“导读”面板（视图 → 面板 → 导读，默认在右侧 AI 面板之后、隐藏）跟随阅读区当前的文件，显示它的导读：文件怎么搭起来，有哪些流程、各部分负责什么、接下来值得问什么。没有导读时点“生成导读”，模型用 AI 提问的同一套只读工具阅读这个文件和它牵涉的代码，再交回一份稿件；设置、密钥、按项目授权与 AI 提问共用（本机地址不询问），授权未给时按钮变为“允许并生成”，状态行说明会把代码片段、提交说明和历史改动发到哪个主机，并注明这项许可与 AI 提问共用。生成期间标题栏显示转圈和“停止”，状态行显示正在读什么；切到别的文件不中断，面板显示“正在为 <文件> 写导读…”，回到原文件时继续显示进度。写作语言跟随应用语言（简体中文或英语）。

稿件是 Markdown 加几种组件：流程（编号步骤，“▶ 播放”每 1.6 秒高亮一步并在阅读区选中它的代码，“■”停止；目标文件已在阅读区时只移动选区、不记入阅读轨迹和后退历史，换文件时才导航一次）、角色表（主线、数据、初始化、辅助、错误处理、样板、测试、其他）、时序图（按参与方分列，箭头流动，系统开启“减少动态效果”时不流动；按面板宽度缩放）、状态（目前按文字列出）、追问（点一下就在 AI 面板里提问）。每份导读必须以追问结尾，没有追问的稿件会被退回。每个代码锚点写成符号名、`符号:起-止`、`L起-止` 或 `文件:起-止`；交稿时 Cairn 逐条核对锚点落在文件和符号的真实行内，不合格的稿件连同“第几行、什么问题、怎么改”退回给模型重写，模型改文字作答而不交稿时提醒一次，再不交则报“模型没有交回导读”。导读里的锚点点击即在阅读区打开对应文件、跳到起始行并选中整段（跨文件也一样）；从导读发起的跳转不让面板换成目标文件，导读留在面板里。长行和长代码在面板内折行，页面不横向滚动；页面不加载任何外部内容，也不导航。

保存：导读按“项目路径 + 文件路径”存在本机（`~/Library/Application Support/Cairn/<包标识>/guides/`），记下写作时文件内容的哈希与稿件格式版本。重新打开时直接显示；文件内容（以阅读区当前快照为准，后台改动需要阅读区刷新后才算）或格式版本变了，状态行提示“文件在写导读之后改动过，内容可能已过时”，按钮为“重新生成”。面板隐藏时不做任何事，显示时再跟上当前文件；阅读区没有打开项目里的文件时显示“打开一个文件查看它的导读”，按钮不可用。

已验证与限制：2026-11-21 打包的测试包（隔离包标识，后台自动化）接本机脚本化 Anthropic 模型原生验证：模型先读文件、交一份含越界锚点 `L99` 的稿件，被退回“L4: 99-99 is not inside the file (1-32)”后交回正确稿件，面板显示正文、流程、角色表、时序图与追问（浅色与 Dark 主题）；点 `request:10-12` 选中第 10–12 行，点 `client.py:3-4` 打开 client.py 并选中两行、面板仍显示 session.py 的导读；播放从别的文件开始时只多一条轨迹，同文件内再播放不增加，■ 能中途停止；生成中切到别的文件显示“正在为 session.py 写导读…”且按钮不可用，切回显示进度，“停止”后显示“已停止。”并保留旧导读；关掉所有标签页后面板回到空状态；追问进入 AI 面板；改动文件并“刷新索引”后提示过时；重启应用后从本机缓存显示。同日用 Anthropic 真实模型为 `Helpers/cairn-ai/src/main.rs` 各生成一次（两个不同档位的模型，当时的稿件格式尚未强制追问）：两份都通过锚点核对；其中一份虚构了一处不存在的矛盾且行号偏一行、把追问写成普通列表，另一份内容准确并用了追问组件；两份都没有画时序图。导读质量取决于用户在设置里选的模型，Cairn 不指定。授权提示的新文案已在面板中看到完整折行显示。强制追问后（格式版本 guide-2）同一文件用真实模型重测：点“允许并生成”后开始生成，约 1.5 分钟交稿，稿件以两个追问按钮结尾，引用的 16 处行号抽查全部与源码一致；中文正文里的逗号和括号是半角。未验证：授权是否在重启后保留（本机地址不询问）、系统“减少动态效果”下箭头停止流动、Auto 主题跟随系统切换明暗时页面重绘（已按外观变化重建页面，未实测）。`calls` 组件未提供，状态组件只是文字；时序图的参与方较多时文字随宽度缩小。

### 多色高亮、括号与块尾注解

“高亮此名称”（默认 `⌃⌘H`，也在阅读区右键菜单）给光标处的标识符加一种颜色，再执行一次取消；右键的“高亮颜色”可以指定颜色，占用该颜色的名字随之取消。最多 6 种颜色同时存在，用满后提示，不挤掉已有的。匹配与单击同名高亮相同：同名、整词、字符串和注释之外，是词法匹配，不代表同一个符号。高亮作用于整个项目窗口的主阅读区、比较两侧和 Context 预览，随阅读会话保存，“清除阅读会话”一并清除；阅读集和悬浮卡片不显示。状态栏左侧的高亮条显示颜色编号、名字和焦点文件中的出现次数，点名字跳到下一处、`⇧` 点击跳上一处；“清除全部高亮”默认 `⌃⌥⌘H`。被单击的名字同时有高亮色时，保留高亮底色并加一圈描边。

光标紧挨 `()`、`[]`、`{}` 时给这一对括号描边，找不到另一半时只给当前括号画虚线；字符串和注释里的括号不参与。“跳到配对括号”默认 `⌃⌘M`；“选中括号内内容”默认 `⌃⇧⌘M`，重复执行逐层向外扩大。Rust 泛型尖括号与 JSX 标签不配对。

Rust、TypeScript/TSX、Go 中，从块头到 `}` 跨 12 行以上的声明块和控制块，会在独占一行的 `}` 后淡色标注块头的简短形式（如 `‹ fn release`、`‹ match self.state`、`‹ acquire()`），最长 40 个字符。`} else {`、`} catch (e) {` 和没有块头文字的裸块不标注；Python 没有闭合符号，不标注。标注不进入文本，不能选中、复制或查找；块被折叠或换行后放不下时不显示。点击标注跳到块头并计入前进/后退，悬停显示完整块头。设置里的“标注长代码块的结尾”可以关闭。

### 概览标记

阅读区右缘有一条约 12pt 宽的竖条，浮在滚动条位置之上、不占阅读宽度；文件里没有任何标记时它完全透明、点击直接落到下面的系统滚动条，出现第一个标记时淡入。它按显示行的比例标出全文：多色高亮按颜色分三列（6 种颜色两两共用一列），查找命中和单击同名的出现画在左列（琥珀色），书签是强调色小方块，比较时的差异用差异三色占满整宽；当前可见范围是一段浅灰底，光标所在行是一条细线。同一像素行的同类标记合并绘制。折叠区里的标记画在折叠行的位置、改成空心。点击标记跳到那一处（必要时展开折叠），点击空白或在竖条上拖动按比例滚动。设置里的“在滚动条旁显示概览标记”可以关闭。

鼠标在可见的竖条上停约 0.3 秒，左侧浮出一张代码卡片：以该位置对应的行为中心显示 7 行代码（与阅读区同样着色，中心行号加粗为强调色），标题写所在函数、行号、这里的标记（最多 3 个）；落在折叠行时注明“已折叠 N 行”。鼠标沿竖条移动时卡片实时跟随，移出、点击或滚动时消失；卡片不接收点击。

可选的**改动时间**（“显示各行最后改动的时间”，默认关闭；开启后竖条只要有内容就常驻）：竖条最右侧 3pt 细列按 Git 最后改动时间着色——一周内、一月内、半年内、一年内由深到浅，未提交的改动用差异“修改”色，一年以前不着色。工作区按 HEAD 计算并叠加尚未提交的内容；切到某个提交时按那个提交计算。计算在后台进行，完成后才出现；不在 Git 仓库内的文件不显示。libgit2 不追踪重命名，重命名之前的历史会算在重命名那次提交上；工作区内容按原始字节与 HEAD 比较，检出时被转换成 CRLF 的文件会整份显示为未提交。在 Cairn 外提交后，执行“刷新索引”才会重新计算。

竖条按行比例定位，不跟随滚动条滑块：TextKit 对还没排版的区域只估算高度，滑块位置会随排版漂移，所以竖条自带可见范围底色，点击、底色和标记始终一致。

设置里的“相对行号”（默认关闭，需先显示行号）让行号栏显示每行与光标所在行的距离，光标行保留实际行号；光标移动时随之更新，尚无光标时显示实际行号。

### 搜索选项

`⇧⌘F` 显示“搜索结果”面板并聚焦输入框；该面板显示时阅读区为当前文件的命中画下划线。输入文本与条件标签表达同一个查询；点击标签可编辑或删除，“+ 添加条件”列出可用条件。一个普通词不显示标签行。语法错误停顿约 600ms 后显示位置和说明，不执行错误查询，并保留上一份结果。

| 写法 | 含义 |
| --- | --- |
| `lock await` | 每个条件都满足；默认在同一文件里出现 |
| `lock OR mutex await` | `lock` 或 `mutex` 至少一个，再同时满足 `await`；OR 比空格结合得紧 |
| `lock -test` | 排除含 `test` 的同一判断单位 |
| `"fn spawn("` | 精确短语，支持转义引号和反斜杠 |
| `/sp[a-z]+n/` | 这一项使用正则，`\/` 表示斜杠 |
| `path:src/ -path:tests/` | 读取前按项目相对路径过滤；多个包含路径取并集 |
| `in:code`、`in:comment`、`in:string`、`-in:comment` | 保留或排除指定语法区域，对包含和排除条件都生效 |
| `near:5` | 每处保留命中的前后 5 行内，其他包含条件都出现，排除条件都不出现 |
| `same:fn` | 按最内层函数或方法判断；可与 `near:` 同时使用 |

查询至少需要一个包含项；纯路径/区域过滤和纯排除不执行。第一版对 `(a OR b)` 这样的未加引号括号分组报语法错误；代码文字 `foo()`、引号短语和正则里的括号仍可使用；排除项不能用 OR 相连。只有已知限定词后的冒号有语法意义，`std::sync`、`http://`、`->`、`-=` 仍可作为普通文字。函数内闭包属于外层函数，嵌套命名函数独立；没有命名函数包围时，最外层闭包或箭头函数成为独立单位。`same:fn` 不返回任何函数单位之外的命中。

大小写开关作用于全部项；全词和整体正则开关只作用于普通词，不改变引号短语和斜杠正则的含义。全词边界采用 Unicode 标识符字符及 `_`，TypeScript/TSX 另加 `$`。从阅读区选中文字带入搜索，或向空输入框粘贴含空格的文本时，自动加引号作为精确短语；手动输入多个词则表示同时满足。路径 glob 支持 `*`、`**`、`?`、`{a,b}`；结尾 `/` 表示目录，无 `/` 的模式可匹配任意层级名称。

搜索结果面板最小 240pt 高，位置和高度随面板布局保存。文件分组标题为展开三角预留独立空间，覆盖说明显示 Rust/Python/TypeScript 等正式名称。结果按文件排列，符号列显示函数/方法或所在类型、impl、模块；连续同一符号用竖线延续。包含条件用四色小块和同色下划线区分，颜色不占用阅读区的高亮底色。多条件、OR 或带 `near`/`same:fn` 的结果按行合并，保留每个条件的命中范围；单个普通词、短语或正则在文件范围内逐处返回，添加路径、区域或排除过滤不改变这一计数方式。

单击结果在预览标签中选中并闪烁命中，焦点留在列表；方向键继续浏览，回车或双击进入阅读区。`⌥⌘G` / `⇧⌥⌘G` 在任意焦点下跳下一处/上一处，文件内查找 `⌘G` 不变。Esc 关闭当前提示，或将焦点还给阅读区，面板保留；面板的 `×` 或“显示/隐藏搜索结果”才关闭它。菜单命令均可在快捷键设置中重绑。

刷新或切换快照会重搜，旧结果标为过期且不能跳转，新结果到达后替换。刷新按文件路径、内容身份和命中字节范围恢复原选中项；尚未到达对应批次或命中已消失时清选，不改选第一条。阅读区的选中位置与滚动锚点分别保存，仅在内容身份一致时原样恢复；没有内容身份的搜索结果不能导航。仅修改查询文字时保留同一快照的旧结果可点击，直到新批次替换。每项目保存最近 20 条明确采用的查询及三个开关状态：回车、点击结果、使用历史、关闭搜索结果面板或关闭窗口/退出时记录；搜索防抖和自动会话保存不把输入中的半截查询加入历史。点击尚未替换的旧结果记录该结果对应的查询。历史可用按钮或输入框行首的 ↑ 调出；最后查询随会话恢复，面板位置随全局布局恢复，索引就绪后自动重搜。“清除阅读会话”一并清除查询历史。会话格式升至 v5，仍能读取 v4；较旧应用不会覆盖它不认识的新格式。

面板底部说明搜索语言、源文件数、路径过滤数、项目规则排除路径数、未搜索的非源码数及正则跳过数；零项省略。包含条件独立受每文件 200 处、每语言搜索会话总计 5,000 处的上限；排除条件只记录文件、行或函数内是否存在，不消耗这些数量限额。扫描仍受 5 秒预算和取消约束；无法确认排除项时不发布该文件的结果，并标明不完整。组合判断也检查取消及时间预算。不完整时显示截断条件和文件标记。列表最多展示 2,000 处，超过时说明。区域取命中起点，和阅读区高亮共用语法分类；这是句法信息，不代表运行时语义。非源码文件仍不参与项目搜索。

输入有焦点且空白、没有结果或结果过多时，停顿约 2 秒后显示建议。可追加的建议以灰字每约 28ms 一字呈现，Tab 接受；其他建议放在输入框下的气泡中，约 180ms 淡入并上移 6pt。Esc 或继续输入关闭提示，同次搜索关闭后不再弹；成功用过的语法在应用级记住，不再推荐。系统“减弱动态效果”开启时直接显示。设置“显示查询提示”可关闭，“恢复阅读器默认值”恢复为开启；`?` 可随时查看完整语法。

命令行 `codeinsight search '<查询>'` 使用相同解析与求值，支持 `--whole-word`；负条件可位于查询开头，查询与 CLI 选项重名时用 `--` 分隔；语法错误在索引前显示可读原因及 UTF-16 位置。文本/JSON 包含条件、符号、覆盖和截断信息。`--repeat N` 在索引一次后重复搜索，结果输出一次，计时另写 stderr。字段与性能复现见[开发说明](development.md#性能复现)。

文件内查找（`⌘F`）仍是单模式搜索，也支持全词；上述组合语法仅用于项目搜索。关系面板的引用查询不受影响。

## 关系、证据与阅读记录

Relations 是静态源码候选关系，不承诺运行时完整调用图。当前是一层结果列表，激活结果换根；前进/后退用于继续探索，不递归展开无限深树。右键关系命令更新关系面板，固定的 Context 不被覆盖。

“显示实现与子类型”（关系面板的“实现”页）只列一层直接结果：Rust trait 列出 `impl Trait for T` 与直接子 trait（`trait Sub: Base`）；Python class 列出直接子类；TypeScript class/interface 列出 `extends`/`implements` 它的 class 和 `extends` 它的 interface。静态候选按基类名查找，`mod.Base`、`Base[T]`、`ns.Base<T>` 取最后一个名字；基类写在同一文件为强候选，所在文件自己定义了同名类型的丢弃，其余交给源码解析，指向别处的丢弃、解析不出的标为可能。已知限制：经 `import … as` 别名、动态生成或 `where Self: Base` 写出的基类找不到；Python 的语言服务器（pyright）不支持实现查询，结果只有静态候选；TypeScript 的语言服务器会额外给出间接子类，作为已验证行列出，查询对象自身不列出。

结果分别描述候选确定性、调用分派、来源、结果集完整程度和分析环境。Verified 表示 provider 给过正向验证结果；Inferred 表示源码推断；Unresolved 表示未解析。Safe 模式限制不能抹掉已有正向结果，Exact 没返回一个候选也不能当作证明它错误。可比较且不同的目标才形成冲突，被修正候选保留在证据视图。

阅读轨迹记录显式语义导航及分支，滚动和标签切换不生成语义边。导航发生时的冻结说明与当前分析说明分开。恢复旧会话不能用新查询悄悄替换冻结证据。

阅读集来自 Freeze Results 或 Freeze Path，保存连续源码片段及其出处、快照、角色和冻结说明。它是可恢复的阅读材料，不是可任意编辑的整理列表。

书签绑定精确快照内容。工作区变化显示 Drifted，必须明确 Re-anchor；位置、文件或 revision 不可用时不静默跳转。最多 32 条记录，每条纯文本笔记最多 2 KiB，原子保存。依赖文件、Cairn 不分析的文件（如 JavaScript）、比较、阅读集和 mini reader 不提供书签，“切换书签”变灰并在提示里说明原因；不实现跨 commit 符号自动映射。

## 字体、快捷键与语言

内置 Light、Dark、SI Classic 三套手调主题，另随附 10 套 base16 方案（Nord、Dracula、Catppuccin 四款、Solarized 与 Gruvbox 各明暗一款）。用户可把 tinted-theming 发布的 base16 `.yaml` 原文放进主题文件夹 `~/Library/Application Support/Cairn/<bundle id>/Themes/`（Settings 的“打开主题文件夹”会先创建它），启动和每次打开设置时重新扫描，不监视文件；缺色、非 base16 或无法读取的文件跳过并记日志。设置里的主题列表分内置、随附、主题文件夹三组，base16 主题显示文件里的 `name`，不翻译。base16 的 16 色按固定规则映射到全部语义角色；状态文字、行号和次要文字向方案中对比度最强的文字色调色，达到内置主题承诺的对比度，因此浅色方案的部分状态色色相会变。“导入主题使用安静的语法着色”默认开启：函数名、属性、参数与正文同色，类型用蓝色；关闭后按 base16 约定完整上色。内置主题不受这个开关影响。Auto 跟随系统外观，在一对浅色/深色主题间切换（默认 Light/Dark，每个槽只列对应明暗的主题）；固定主题不受系统外观影响。已选主题的文件被删除后回到 Auto。主题的明暗决定窗口外观；文档面板的反色、系统控件和设置窗口只跟随明暗，不跟随调色板。

代码字体选择本机等宽字体，编程连字可为 Font Default、On、Off。缺失字体回退系统字体但保留用户选择，Refresh Fonts 用于重新发现字体；产品不分发第三方字体。

主 Reader、比较、Context、阅读集和设置预览使用同一代码字体策略。字体/颜色变化应保持源码、选区和折叠；超过 8,000 行或源行超过 64 KiB 时避免同步全文精确重排，不保证巨行的精确像素锚点。

Settings → 快捷键提供搜索、按键搜索、录制、冲突替换及恢复默认。菜单命令与阅读器鼠标手势可配置；系统保留组合锁定，面板内方向键/回车/Esc 只读显示。覆盖项只保存与默认表的差异，更新菜单、工具栏和命令面板；关闭设置、切页或切窗必须结束录制，按键搜索捕获一次即结束。当前只有默认方案，不提供导入导出。

产品界面支持英文和简体中文，跟随系统应用语言设置，其他语言回退英文。源码、路径、工具名、用户笔记、稳定存储键和原始工具诊断不翻译。新冻结的轨迹/阅读集保存双语说明，旧版纯文本证据保持原文。

## 非源码预览

Markdown 使用只读富文本；Jupyter Notebook（`.ipynb`，nbformat 4）按同一渲染显示：Markdown 单元原样，代码单元按内核语言着色，输出以引用块列在其下——流和错误（去除 ANSI 颜色）为等宽文本，PNG/JPEG/GIF 图像内联显示，其他富输出（HTML 表格、组件、LaTeX）显示其 `text/plain` 形式；单元附件图片不显示，无法解析的 notebook 作为普通文本预览。HTML 使用受控 WKWebView（关闭 JavaScript、网络及本地子资源），图片和 PDF 使用只读预览，其余严格 UTF-8 文本可选择复制；未知二进制明确为不支持。

配置、脚本，以及 Cairn 不分析的源码语言（C/C++、Objective-C、C#、Java、Kotlin、Swift、PHP、Perl、CSS、SQL、Pascal、Visual Basic、Ada、汇编）按后缀做词法着色：关键字、注释、字符串、数字、预处理指令、注解和形如 `name(` 的调用，与 Source Insight 语言文件同一层次，不提供跳转。`.h` 按 C++ 着色。项目内超过约 20 万字节的 JS/JSX（`.js`、`.jsx`、`.mjs`、`.cjs`），以及依赖和项目外的 JS/JSX，是预览，用内置的 TSX 语法树着色，超过约 20 万 UTF-16 单元时显示为不着色等宽文本（预览在主线程同步着色），所以超大的 JS 文件实际都不着色；其他格式的上限为 150 万。`.rs`、`.py`、`.ts`、`.tsx`、`.go` 在项目未分析该语言时（只在切换到工作区没有该语言的 commit 时出现）同样以对应语法树预览着色。Markdown 代码块使用同一套规则。

这些着色预览可以像源码一样逐块折叠（行号栏三角、折叠占位符、“展开或折叠” `⌃⌘[`），复制仍来自原文：内置语法树（JS/JSX 及未分析时的 `.rs`、`.py`、`.ts`、`.tsx`）用语法折叠；TOML、INI 按 `[节]` 折叠到下一个节；Diff 按文件（`diff `）和 hunk（`@@`）折叠；其余格式（YAML、JSON、XML、Shell、Dockerfile、Makefile、其他语言、Jinja 及无格式文本）按缩进折叠——一行折叠其后缩进更深的行，YAML 中 `- ` 列表项视为比所在键深一级。词法折叠不认括号，压缩成一行的 JSON 或括号独占一行时块头留在外层。Markdown 预览按标题折叠：悬停标题时左侧页边出现箭头，点击或 `⌃⌘[`（光标所在节）把该标题之后、下一个同级或更高级标题之前的内容收起，收起的标题保留箭头；跳到被收起的锚点会先展开。跨折叠复制得到完整的渲染文本。HTML、纯文本文档（`.txt` 等）、图片和 PDF 不折叠。

Markdown 按 GitHub 规则为标题生成锚点（小写、去标点、空格变连字符、重名加 `-1`），`#标题` 链接在当前预览内滚动到该标题，`other.md#标题` 先打开文件再滚动；页内跳转不进入前进/后退历史。中文正文里 `**` 紧贴标点与汉字时（如 ``**命令`code`**继续``）按加粗处理，`_` 仍按 CommonMark。解析器为 Foundation：脚注 `[^1]` 与 `$…$` 公式按原文显示，链接文字内的加粗/斜体丢失，普通 Markdown 段落中的 `<kbd>`/`<sub>` 等内联标签只保留文字。

Markdown 的内嵌 HTML 块由系统 HTML 解析器解析为原生富文本，保留标题、段落、表格和常用行内样式。HTML 和 Markdown 标题共享折叠和锚点规则。图片按正文或单元格可用宽度等比缩放，远程图片显示替代文本。内嵌 HTML 块不执行脚本、不加载样式表或其他远程资源。

Markdown/HTML 的项目内链接可导航，前进/后退跨预览可用，commit 标签读取对应快照字节。非源码预览不提供符号大纲、关系、书签、比较、Reading Height 或搜索控件；外链不打开。
