# 阅读体验补强计划（未实现）

> 状态：需求与决定已确认（2026-10-04），待实施。**以下能力均未实现**，不得写入 README 或 [产品说明](product.md) 作为现有功能。
> 原型：[reader-qol-prototype.html](reader-qol-prototype.html)（浏览器打开，可切三主题）。
> 完成后把仍有效的行为归入 `product.md`，删除本文件和原型。

这组需求来自对照 Source Insight 时发现的日常阅读便利功能。它们不改变产品方向，复用已有的装饰层、折叠拓扑、副阅读区和搜索服务；共同目标是让人在长文件、多文件之间读得更省力。

## 范围

| 编号 | 功能 | 一句话 | 主要复用 |
| --- | --- | --- | --- |
| Q1 | 多色持久高亮 | 给几个名字各涂一种颜色，跨文件保留 | `DecorationComposer` 装饰层、`IdentifierIndex` |
| Q2 | 块尾注解 | 长代码块的 `}` 后淡色显示它属于谁 | `FoldRegion` 的 header/body 范围 |
| Q3 | 括号配对 | 光标挨着括号时标出另一半，可跳转 | tree-sitter 语法树 |
| Q4 | 滚动条概览标记 | 在阅读区右缘看到全文的高亮、命中、书签分布 | Q1、查找、书签的现有数据 |
| Q5 | 分屏阅读 | 任意两个文件左右并排 | Compare 已有的 `secondaryReaderController` |
| Q6 | 搜索全词与路径过滤 | 项目搜索和文件内查找加“全词”，项目搜索加包含/排除路径 | `ContentSearchQuery`、`SnapshotSearchService` |
| Q7 | 项目排除规则 | 用户自定义哪些目录不参与阅读和索引 | `skippedDirectories`、Refresh Index |

明确不做：

- **条件编译感知**（未激活分支变灰）：需要拿到当前生效的 feature/target，且要诚实表达 Safe 模式下拿不到的情况，属于语义功能，另立。
- **Clip Window、自定义命令、宏语言**：与只读和 Safe 模式冲突；扩展性需求留给后续的 Agent/查询接口方向。
- 编辑类功能（补全、重命名、片段、格式化）继续不做。

## 共同约束

1. **不改变排版**。Q1–Q4 只画背景、描边或覆盖层，不改字号、行高、换行，不进入文本存储；复制、查找、选区结果不受影响。
2. **诚实标注**。Q1 是“同名”（词法）高亮，不是“同一符号”；界面和帮助文案不能暗示语义判断。Q6/Q7 的过滤必须在结果里说清楚排除了什么。
3. **三主题统一**。Light、Dark、SI Classic 各有一套取值，与已有的同名高亮（琥珀）、diff 色、选区色、Verified/Inferred 色相区分。
4. **大文件不退化**。只为可见区域计算装饰，沿用同名高亮的二分查找方式；超过 8,000 行的文件不做同步全文扫描。Q4 的全文统计放后台，未就绪时不画。
5. **键位进入集中表**。新命令都注册到 `KeyBindings` 默认表，可在设置里改；默认快捷键见“已决定”D7，需过冲突校验。
6. **只读边界**。Q7 的规则只保存在应用数据目录，不读取也不写入仓库里的任何文件。

## Q1 多色持久高亮

**场景**：追踪 `state`、`waker`、`permits` 三个变量在一个长函数和相邻文件里怎么流动。现在的同名高亮一次只有一个，换个地方点击就没了。

**行为**

- **Q1.1** “切换高亮”命令：光标在标识符上时，为这个名字加上下一种可用颜色；再执行一次取消。右键菜单提供“高亮此名称”和颜色子菜单，可以指定颜色。
- **Q1.2** 最多 6 种颜色同时存在。用满后再加，提示“已用满 6 种颜色”，不自动挤掉旧的。
- **Q1.3** 匹配规则与现有同名高亮一致：同名、区分大小写、整词，排除字符串和注释（`IdentifierIndex` 已经这样做）。第一版只支持标识符，不支持任意选中文本。
- **Q1.4** 作用范围是整个项目窗口：主阅读区、分屏（Q5）、Compare 两侧、Context 预览都显示。阅读集和悬浮卡片第一版不显示。
- **Q1.5** 状态栏左侧出现高亮条：每个高亮显示色块、名字和当前文件内的命中数；点名字跳到当前文件里的下一处，`⇧` 点击跳上一处；条尾有“全部清除”。没有高亮时条不出现。
- **Q1.6** 随项目阅读会话保存和恢复；“清除阅读会话”一并清除。
- **Q1.7** 层级：选区 > 多色高亮 > 同名高亮 > 当前行。同一个名字既被多色高亮又是当前点击的同名高亮时，保留多色高亮的底色，另加一圈描边表示“当前点中的这组”，不改变背景色。
- **Q1.8** 颜色带编号（1–6），高亮条上显示编号，给色觉差异用户一个非颜色的区分方式。

**颜色**（底色；需在原型中目测确认可读性）

| 编号 | Light | Dark | SI Classic |
| --- | --- | --- | --- |
| 1 青 | `#CDE6E4` | `#1E3B3A` | `#BFEFEF` |
| 2 紫 | `#E3DAF0` | `#352C47` | `#E6D5FF` |
| 3 绿 | `#D8E8C8` | `#2A3A22` | `#CFF5C4` |
| 4 玫 | `#F2D6D9` | `#45282C` | `#FFD3DC` |
| 5 蓝 | `#D3DEEF` | `#23324A` | `#CCE0FF` |
| 6 橙 | `#F4DCC2` | `#45321D` | `#FFDDB3` |

琥珀/米黄留给现有同名高亮（Light `#ECE3C6`、Dark `#2E2F21`、SI `#FFF1C2`），不进入这组颜色。

**验收**：打开 tokio 某个长文件，高亮三个名字 → 切到另一个文件仍可见 → 三主题截图检查正文可读 → 退出重开后恢复 → 选区、复制结果不变。

## Q2 块尾注解

**场景**：读到第 400 行的一个 `}`，不知道它结束的是 `match`、`impl` 还是函数。

**行为**

- **Q2.1** 语言：Rust、TypeScript、TSX。Python 没有闭合符号，不显示。
- **Q2.2** 显示条件：块从开头到 `}` 至少跨 **12 行**（阈值固定；设置里只提供整体开关）。覆盖声明（函数、方法、impl、trait、mod、class、interface、namespace）和控制块（if/else、for、while、loop、match、switch）。
- **Q2.3** 内容取块头的简短形式，最长约 40 个字符，超出截断：`fn spawn_blocking`、`impl<T> Mutex<T>`、`match self.state`、`if permits > 0`。
- **Q2.4** 样式：行尾空两格，比正文小一号，斜体，第三级文字色，前面带一个 `‹`。不能像真实注释那样以 `//` 开头，避免和源码混淆。
- **Q2.5** `} else {`、`} catch (e) {` 这类本身是新块开头的行不显示；没有块头文字的裸 `{ … }` 块也不显示。`});`、`};` 照常显示在行尾。
- **Q2.6** 点击注解跳到块头所在行，计入前进/后退。悬停时显示块头完整的一行。
- **Q2.7** 块被折叠时 `}` 不可见，不显示注解。开启换行且行尾空间不够时不显示，绝不为此换行。
- **Q2.8** 注解不可选中、不进复制、不参与查找。

**验收**：Rust/TS 各一个含长 match/switch 的文件，Python 文件无注解；折叠、换行、字号变化后没有错位；复制包含 `}` 的选区，结果里没有注解文字。

## Q3 括号配对

**行为**

- **Q3.1** 光标紧挨 `(` `)` `[` `]` `{` `}`（在前或在后）时，给这一对括号画细描边（强调色）。三门语言都支持。
- **Q3.2** 配对来自语法树，字符串和注释里的括号不参与。找不到另一半时（语法错误或文件被截断），只给当前括号画虚线下划线，用 Unresolved 色。
- **Q3.3** 命令“跳到配对括号”：光标移到另一半，必要时滚动；另一半在折叠区里时，沿用现有导航进入折叠区的展开行为。
- **Q3.4** 命令“选中括号内内容”：选中最内层一对括号之间的文本，方便复制。重复执行逐层向外扩。
- **Q3.5** Rust 泛型尖括号、JSX 标签不在第一版范围内。

**验收**：三种语言的嵌套括号；字符串里的括号不配对；跨折叠区跳转；在超过 8,000 行的文件上移动光标不卡顿（取少量样本看方向即可）。

## Q4 滚动条概览标记

**场景**：高亮了一个名字以后，想知道它在全文哪些位置出现、是否集中在某一段。

**行为**

- **Q4.1** 阅读区右缘有一条约 10pt 宽的竖条，与滚动条并排，纵向比例对应全文。
- **Q4.2** 标记种类和画法：

  | 来源 | 画法 |
  | --- | --- |
  | 多色高亮（Q1） | 对应颜色的短横线，按编号分列（右侧三列，最多六种时两两共列） |
  | 查找命中 / 同名高亮 | 琥珀色短横线，画在左列 |
  | 书签 | 小方块，强调色 |
  | Compare 的 diff | 沿用 diff 三色，整条宽度 |
  | 光标所在行 | 一条贯穿的细线 |

- **Q4.3** 竖条的位置换算必须和滚动条滑块一致，点击某个标记后，滑块应该落到附近。TextKit 2 对未布局区域只有估算高度，这一点是主要实现风险，先做技术验证再定方案（可退回按行号比例换算）。
- **Q4.4** 折叠时竖条表示当前可见内容：折叠区内的标记合并到折叠行的位置，画成空心。点击空心标记会展开该折叠并跳过去。
- **Q4.5** 点击标记滚动到对应位置；悬停显示“第 N 行 · 名称”。在竖条上拖动等同于拖动滚动条。
- **Q4.6** 同一像素行有多个标记时合并绘制，不逐个叠加，保证大文件的绘制成本受竖条高度限制。
- **Q4.7** 设置里可以关闭竖条。滚动条为“自动隐藏”样式时，竖条仍常驻显示。

**验收**：一个 3,000 行以上的文件，查找 + 两个多色高亮 + 两个书签，点击标记后落点基本准确；折叠后标记合并；三主题截图。

## Q5 分屏阅读

**场景**：一边读 trait 定义，一边读它的实现；或者一边读调用方，一边读被调用方。

**行为**

- **Q5.1** 入口：“在右侧打开”出现在文件树、标签页、关系结果和 Context 的右键菜单里；命令“分屏打开当前文件”在右侧打开当前文件的同一位置。
- **Q5.2** 右侧是**单文档阅读区**，没有自己的标签栏。顶部显示文件路径和关闭按钮；在右侧再打开别的文件时直接替换。
- **Q5.3** 焦点所在的一侧决定 Context、Relations、Outline 和状态栏显示的内容。焦点一侧的顶部有一条 2pt 强调色边。
- **Q5.4** 在右侧 `⌘` 单击、或双击 Context 正文，都在右侧打开目标，不跳回左侧。
- **Q5.5** 前进/后退作用于焦点所在的一侧，两侧各自记录历史。阅读轨迹仍是一条，不记录发生在哪一侧；从轨迹恢复节点时在焦点一侧打开。
- **Q5.6** 与 Compare 互斥：进入 Compare 时收起分屏，关闭 Compare 后恢复原来的分屏。Focus 预设隐藏右侧。
- **Q5.7** 分屏状态、右侧文件和位置随阅读会话保存和恢复。
- **Q5.8** 窗口太窄、两侧都放不下最小宽度（各 320pt）时，先收起侧栏；仍放不下就不打开分屏，并提示原因。
- **Q5.9** 书签、折叠、Q1–Q4 在右侧同样可用。右侧文件被移出项目或不可读时，显示和左侧一致的状态页。

**验收**：左右各开一个文件，切换焦点后 Context/Outline 跟着变；右侧 `⌘` 单击；进出 Compare；退出重开后恢复；窄窗口行为。

## Q6 搜索全词与路径过滤

**行为**

- **Q6.1** 项目搜索（`⇧⌘F`）和文件内查找（`⌘F`）都增加“全词”开关，与现有的“区分大小写”“正则”并列，图标沿用 macOS 常见的 `ab` 下划线样式。
- **Q6.2** 全词的定义：命中两端都不能紧挨标识符字符（Unicode 字母、数字、`_`，TS/TSX 另加 `$`）。与正则同时开启时，对正则的每个命中做同样的边界检查。
- **Q6.3** 项目搜索可以展开一行“包含 / 排除”路径输入框，逗号分隔的 glob：`*`、`**`、`?`、`{a,b}`；以 `/` 结尾表示目录；含 `/` 的模式从项目根开始匹配，不含 `/` 的模式匹配任意层级的文件名或目录名（与 `.gitignore` 习惯一致）。
- **Q6.4** 结果头部写明范围：“在 412 个文件中搜索 · 按路径排除 37 个”。现有的截断与完整性提示保持不变。
- **Q6.5** 开关和路径输入按窗口记忆，不进入阅读会话。
- **Q6.6** 关系面板的 references 查询不受这些开关影响。

这一项与后续“可组合搜索”方向有关：`ContentSearchQuery` 增加的 `wholeWord`、`includeGlobs`、`excludeGlobs` 字段应能被将来的查询表示直接容纳，不做一次性 UI 特判。

**验收**：全词边界做成属性测试，覆盖 Unicode 标识符、行首行尾、正则组合；glob 匹配取少量代表性路径；原生应用里检查一次结果头部。

## Q7 项目排除规则

**场景**：仓库里有 `vendor/`、`third_party/`、生成的 `*.pb.rs`，既拖慢索引又污染搜索；反过来，有的项目把源码放在被默认跳过的 `build/` 目录里。

**行为**

- **Q7.1** 每个项目有一个“排除规则”页（从项目菜单进入）：一组 glob，每行一条；以 `!` 开头表示“包含”，可以把默认跳过的目录（`build`、`dist` 等）重新纳入。匹配语法同 Q6.3；默认跳过先生效，用户规则按顺序覆盖，最后一条命中的规则决定结果。
- **Q7.2** 默认跳过的目录以只读列表显示在页面上方，说明它们的来源。
- **Q7.3** 被排除的路径不进文件树，不建索引，不参与搜索和关系查询。
- **Q7.4** 对工作区快照和 commit 快照同样生效。文件树底部和搜索结果头部常驻显示“按项目规则排除 N 个路径”，点击可以临时显示被排除的文件（灰色）。
- **Q7.5** 规则改变后走现有的 Refresh Index 流程，保留标签、阅读集、书签、轨迹和布局。已打开的被排除文件保持打开，标记“已排除，不参与索引”。
- **Q7.6** 规则只保存在应用数据目录，按项目实际路径区分，不读取仓库里的 `.cairnignore` 之类文件。原因：被审阅的仓库不能自己决定对审阅者隐藏哪些文件。
- **Q7.7** Exact 语言服务器不受影响；经 Exact 跳进被排除的文件时，像依赖文件一样只读打开并加标注。
- **Q7.8** `WorktreeSnapshot` 和 `ProjectIndexer` 中两份 `skippedDirectories` 合并为一处，由规则层统一判断。

**验收**：排除 `vendor/` 后文件树和搜索都不出现，提示数字正确；`!build/` 让 `build/` 重新可见；改规则后标签和书签还在；commit 快照下同样生效。

## 实施计划

五个切片，依赖关系：P1 → P2；P3 可与 P1 并行；P4 在 P1 之后（右侧也要显示 P1 的装饰）；P5 在 P3 之后（共用路径匹配）。每个切片完成后，把已实现的行为写进 [product.md](product.md)，从本文删除对应的 Q 节；全部完成后删除本文和原型。

各切片共同要求：

- 新命令注册进 `KeyBindings.swift` 的默认表和 `CommandID`，菜单通过现有的 `appendMenuItem` 接入；所有新文案同时加 `en.lproj` 和 `zh-Hans.lproj`，通过 CI 的本地化检查。
- 新设置项加在 `ReaderSettings`（`CodeInsightReaderCore`），在设置窗口的“高级排版”区提供开关，“恢复阅读器默认值”要覆盖它们。
- 主题取值加在 `ReaderSettings.swift` 现有的 `…RGB(isDark:)` 一组函数旁边，三主题各一套。
- 验证按 [testing.md](testing.md) 的风险分类：核心机制写属性/不变量测试；跨模块的持久化写少量集成测试；界面行为用打包后的原生应用实测并截图，结果分 PASS / FAIL / BLOCKED 记录。
- 不新增依赖。AppKit 只进入 `CodeInsightApp` 和 `CodeInsightReaderUI`。

### P1 阅读区装饰：Q1 + Q2 + Q3

**Q1 多色持久高亮**

1. 状态：项目窗口持有一个有序列表 `[(name: String, color: UInt8)]`，放在 `AppModel`（每个项目窗口一个），不另建模型类型。切换、清除、跳转都是它上面的简单操作。
2. 匹配：给 `IdentifierIndex` 加按名字取全部出现位置的查询（现有的 `names` 和 `postingOffsets` 已足够）。排除字符串和注释的规则沿用现有实现。
3. 渲染：`DecorationRun` 增加 `highlightColor: UInt8?` 和 `occurrenceRing: Bool`，`DecorationComposer` 增加一层；`ReaderTextView` 中与 `setOccurrences` 并列的入口接收这一层，只对可见片段做二分取范围。层级按 Q1.7：多色高亮与同名高亮重合时，保留底色、加描边。
4. 显示范围：主阅读区、Compare 两侧、Context 预览都订阅同一个列表。阅读集和悬浮卡片不显示。
5. 状态栏高亮条：放在主窗口状态栏左侧，计数取焦点阅读区当前文件；点击跳到下一处，`⇧` 点击跳上一处；跳转复用现有“滚动到位置并闪烁”的路径。
6. 持久化：`SessionCodec` 的 `Envelope` 升到 schemaVersion 4，增加可选的 `highlights` 字段。旧版应用遇到 v4 会按“较新格式”处理，不覆盖。“清除阅读会话”一并清除。

**Q2 块尾注解**

1. 数据：从 `FoldTopology` 里取 `container`、`declaration`、`block` 三类区域。`bodyRange.upperBound` 所在行必须以 `}` 开头；块头文字从 `headerRange` 取。语言只限 Rust、TS、TSX。
2. 生成文字的规则在 `CodeInsightReaderCore` 里实现为纯函数：函数取 `fn 名称` / `名称()`，其余去掉可见性修饰和末尾的 `{`，截断到 40 个字符；块头为空的裸块不生成。
3. 绘制：在 `ReaderTextView` 的背景绘制回调（`backgroundHandler`，当前画当前行和主选区）之后画在行尾，不写进文本存储。点击命中由阅读区处理，跳转记入前进/后退。
4. 设置：`blockEndAnnotations`（默认开）。阈值固定为 12 行，不提供设置项。

**Q3 括号配对**

1. 数据：在准备文档派生数据时（与 `IdentifierIndex` 同一阶段，经 `ReaderDerivedDataStore` 缓存），从 tree-sitter 语法树收集括号对：只取语法节点的定界符，字符串、注释、错误节点里的括号不收。结果是按位置排序的配对数组，没配上的单独记录。
2. 光标挨着括号时，两端各加一层描边装饰；没配上的加虚线下划线（Unresolved 色）。
3. 两个命令：“跳到配对括号”复用现有的光标移动和折叠展开路径；“选中括号内内容”在同一个括号上重复执行时逐层向外扩大。

**P1 验证**

- 属性测试：括号配对在随机嵌套、混入字符串/注释、截断输入下，配对结果对称且互为对方；块尾注解文字的生成对 Unicode 标识符和超长块头不越界。
- 集成测试：schemaVersion 4 的编码解码往返；v3 会话照常读取；旧版本拒绝覆盖 v4 的行为保持不变。
- 原生应用：用 tokio 的一个长文件按 Q1–Q3 的验收步骤走一遍；Light、Dark、SI Classic 各截一张图；复制包含 `}` 和高亮名字的选区，粘贴结果与源码一致。

### P2 概览竖条：Q4

1. **技术验证（先做，结论写回本节）**：在 3,000 行和超过 50,000 行的文件上，分别测换行开/关和折叠后的情况，比较两种换算方式与滚动条滑块位置的偏差：按 TextKit 2 的布局估算高度换算，和按显示行号比例换算。偏差小于竖条高度的 2% 就采用行号比例换算，它不依赖未布局区域的高度。
2. 视图：新建一个窄视图，放在 `ReaderViewController` 的滚动视图右侧。左侧现有的 `ReaderRulerView` 是行号和折叠槽，不复用。
3. 数据：标记来源包括 P1 的高亮列表、同名高亮和查找命中（它们共用 occurrence 层）、书签（`bookmarkMarkers`）、Compare 的 diff 标记、光标行。按像素行聚合后再绘制，绘制成本只取决于竖条高度。
4. 折叠：折叠区内的标记合并到折叠行，画成空心；点击空心标记时展开这个折叠再跳转。
5. 设置：`overviewRuler`（默认开）。

**P2 验证**：技术验证的数据写在本节；在原生应用里点击标记，检查落点与 Q4 的验收步骤一致；三主题截图。

### P3 搜索全词与路径过滤：Q6

1. 在 `CodeInsightCore` 新建一个路径匹配类型，实现 Q6.3 的 glob 语法，供 P3 和 P5 共用。
2. `ContentSearchQuery` 增加 `wholeWord`、`includeGlobs`、`excludeGlobs`，默认值保持现有行为。`SnapshotSearchService` 读文件内容之前先按路径过滤；全词检查放在每个命中产生之后。`SearchBatch` 增加被排除的文件数。
3. 关系面板 references 查询所用的 `searchReferences` 不传这些字段（Q6.6）。
4. 界面：`SearchPanel` 的大小写、正则按钮旁增加“全词”按钮，下面增加可展开的包含/排除输入行，结果头部显示范围。`ReaderViewController` 的查找栏同样增加“全词”。按窗口记忆，不写入会话。

**P3 验证**：全词边界和 glob 匹配写属性测试，覆盖 Unicode 标识符、TS 的 `$`、行首行尾、正则组合、`**` 与 `{a,b}`；搜索服务写一个集成测试，验证路径过滤后的计数和截断状态；原生应用里检查一次结果头部。

### P4 分屏阅读：Q5

1. 复用 `secondaryReaderController`，给它加一个模式：比较 / 参考。参考模式隐藏比较控件，顶部显示路径和关闭按钮。`PanelLayoutDescription` 的 `readerSplit`、`secondaryReaderFraction` 沿用。

### P5 项目排除规则：Q7

1. 规则判断：在 `CodeInsightCore` 中实现一个函数，输入是默认跳过的目录、用户规则和路径，输出是“排除 / 包含”及原因。默认跳过先生效，用户规则按顺序覆盖，最后一条命中的规则决定结果。`WorktreeSnapshot` 和 `ProjectIndexer` 里各自的 `skippedDirectories` 删除，统一调用这个函数。
2. 存储：放在应用数据目录，文件名用 `SessionCheckpointStore.projectKey(for:)` 生成，原子写入。不读取仓库里的任何规则文件。
3. 生效位置：工作区捕获、`ProjectIndexer` 枚举源文件、commit 快照生成清单（`ProjectIndexer` 构造 `SnapshotManifest` 处）。被排除路径的数量随快照一起提供给文件树和搜索。
4. 规则改变后调用 `AppModel.refreshIndex(leaving:)`，保留标签、阅读集、书签、轨迹和布局。已打开的被排除文件保持打开，并显示“已排除，不参与索引”。
5. 界面：项目菜单里打开规则页（内置跳过目录只读显示，用户规则可编辑）；文件树底部显示排除计数，并提供“显示被排除的文件”开关。
6. Exact 跳进被排除的文件时，按依赖文件的方式只读打开并加标注。

**P5 验证**：规则判断写属性测试（顺序覆盖、`!` 重新包含、目录与文件模式）；集成测试覆盖：排除后清单与搜索结果一致，改规则后刷新索引，会话状态保持；原生应用按 Q7 验收步骤走一遍，包括一个 commit 快照。
