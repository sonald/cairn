## 如何维护

- 行为改变时，直接改对应主题的现行描述，并删除被取代的要求。不追加“旧规则 + 新规则 + 后续修订”让读者自行裁决。
- 设计意图与已经实现的行为分开。尚未实现的提议不写成产品保证；没有具体任务的远期路线不作为约束。
- 临时实施计划仅服务正在进行的工作。完成后把仍有效的结论归入主题文档，移除步骤清单、里程碑交接和重复验收叙述。
- 测试结果记清源码版本、环境、执行范围与实际结果。失败、跳过、阻塞分别记录，不能用历史 PASS 代替当前验证。
- 原始证据默认保存在 `.build/` 或任务产物中；只有解释长期机制、当前限制或可复现取舍所必需的少量证据进入仓库。不要提交整套重复 CI 日志和每轮截图。
